# v2.2 BENCHMARK 需求整理（v2）

## 0. 定位：两个域，不是一次升级

| | demo 站（现状） | bench 站（v2.2 新增） |
|---|---|---|
| 基调 | 用户共创，限制宽松 | 严格信息标准 |
| 内容 | 任意 AI 网页 demo | 满足 bench 信息标准的作品 |
| 门槛 | 模型标签兜底即可 | harness/档位/灰测渠道等强制 |
| 关系 | 不受影响 | 独立域，作品可来自 demo 站 |

**核心原则：bench 的严格性只作用于 bench 域内，绝不回流污染 demo 站的宽松上传。**

## 1. 需求条目

### B-1 用户出题（上传 bench 题目 + 测试环境）
- 用户可创建 bench：题面 + 测试环境 + 信息标准要求 + 可选量化指标
- 出题走审批（用户提议 → 管理员确认），不直接生效
- 测试环境要素：harness、档位、联网限制、评分/量化方式

### B-2 用户做题上传（上传 bench 的 demo）
- 用户可「挑战某 bench」并上传作品
- 作品必须满足该 bench 声明的信息标准，缺必填项不得进入该 bench
- 上传入口：bench 详情页「挑战此题」→ 带标准表单的上传

### B-3 信息标准（bench 域内强制）
| 要素 | 级别 | 说明 |
|---|---|---|
| 灰测渠道 + 日期 | 灰测模型时强制 | 不纠结具体型号，渠道+日期即可 |
| harness | 强制 | 在哪个 harness 上测的 |
| 档位 | 强制 | 什么档位（thinking 档/默认档等） |
| 时间 / 轮数 / 成本 | bench 可要求 | 可要求备注 |
| 开发环境 / 脚手架 | 可选（程序类） | 更详细的环境要求 |
| 禁止联网等约束 | 题面注明 | 展示 + 上传时提醒 |

### B-4 可量化排行榜
- bench 可声明量化指标（分数/时间/成本等）
- 可量化的 bench → 题下直接显示排行榜（按指标排序）
- 不可量化 → 不显示排行榜，保留作品列表

### B-5 约束注明
- bench 可声明「禁止联网」「限时」等约束
- 题面展示 + 上传挂题时显式提醒

## 2. 用户流程

```
出题流：bench 页 →「提议新题」（题面+测试环境+信息标准+量化方式）
      → 候选 → 管理员批准 → bench 上线
做题流：bench 详情 →「挑战此题」→ 上传（强制填信息标准）
      → 校验通过 → 挂入 bench → 进作品列表/排行榜
```

## 3. 建议（关键决策）

### 3.1 域边界：bench 作品 = 满足标准的 demo 子集
**建议**：bench 不另立作品库，而是「demo 站的作品 + 满足 bench 标准的挂载」。用户上传一次，普通展示走宽松规则；若同时声明挑战某 bench，则额外接受该 bench 的信息标准校验。这样：
- demo 站零改动、零污染
- bench 作品天然可点回 demo 详情（欣赏、会话日志、评分都在）
- 用户不用传两遍

### 3.2 与现有 Task 体系的关系
现状已有：Task 题目、挂题候选（`task_match`）、按模型对比行、run 元数据列（轮数/时间/平台）、灰测兜底值。

**建议**：bench = 现有 Task 的「严格模式扩展」，而非新造平行实体：
- 普通 Task 保持现状（宽松，可挂题）
- Bench 型 Task 增加「信息标准配置」（harness/档位/灰测渠道/量化指标/约束声明）
- 挂题校验按 bench 配置执行，普通 Task 不校验
- 复用：`entity_suggestions` 候选审批、`task_service` 挂题、对比行、上传向导挂题块

### 3.3 信息标准的数据形态
**建议**：bench 级配置（JSON 字段存标准定义），而非全站统一加列：
- 每个 bench 声明自己的必填集（A bench 要成本，B bench 不要）
- 上传时按该 bench 配置动态渲染表单 + 校验
- 已提交的字段落 demo 的 run 元数据列（轮数/时间已有，成本/渠道/日期/harness/档位新增）

### 3.4 排行榜防刷
**建议**：量化指标由用户提议、管理员批准时确认（指标口径写进 bench 题面）。排行榜只统计「信息标准完整 + 已批准挂载」的作品，缺字段自动降级出榜。

### 3.5 灰测模型
**建议**：沿用现有兜底（`ds-unknown` + `model_hint`），bench 域内强制补「渠道 + 日期」两字段。渠道建议枚举（官方灰测/DSH 灰测/网传等），日期为测试日期。

## 4. 非目标

- 不做自动评测/自动打分（LLM 只建议不决定）
- 不强制所有 demo 挂 bench
- 不因 bench 收紧 demo 站的上传规则
- 不做物理删除
