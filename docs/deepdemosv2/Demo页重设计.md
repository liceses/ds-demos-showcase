# Demo 详情页重设计（能力 → 信息架构 → 界面）

日期：2026-08-31 ｜ 状态：**第 1 期已实现并实测**（第 2、3 期为清单）
方法同后台那份：先把页面现在**实际承担的能力**点出来，再诊断，再定结构。

> **第 1 期实测（CDP 断言）**：桌面 1440×1000 —— `dv-shell` ✓、预览 `position: sticky` ✓、评分在事实卡内 ✓、tab 只剩「时间线/会话日志/讨论」✓、描述提到正文 ✓、标题落在 y=148（首屏可见）；窄屏 390×844 —— 预览退回普通流、事实卡排到预览之前，标题从 **718px 修到 150px**（原来手机上首屏看不见作品叫什么）。
> 另修一处只有看图才会发现的缺陷：`RatingWidget` 按整宽设计，塞进右栏**溢出卡片右边界** → 加窄栏适配（折行而非隐藏分布图）。

## 2. 诊断（每条挂原理，与上传页同一套尺子）

| # | 事实 | 问题 | 原理 |
|---|---|---|---|
1 | 预览 iframe 与描述/标签/对比同列滚动 | 想"玩一下"得先滚过一堆字；**作品本体不是主角** | 层级倒置 / figure-ground |
2 | 三种"相关"长得一模一样（同提示词 / 同题 / 推荐） | 语义完全不同却同一形态，用户无法区分"严格复现"与"随便推荐" | 信息科学：**范畴混淆**；同形即同类 |
3 | 会话日志（真实 AI 生成过程）藏在第 3 个 tab | 本站**最独特的证据**被埋没，别处看不到 | 差异化内容应获得一等版面 |
4 | 评分入口在 hero 角落 | 评分是 v2 唯一的社区信号源，入口弱 → 数据饥饿 | 主任务需要主版面；**执行落差** |
5 | timeline / session 原始文件 / 编辑删除 与访客内容混排 | 受众混排（同上传页的老病） | 受众分离 |
6 | 点模型署名就离开本页 | 图谱是 v2 的核心价值，但"去看一眼"的代价是丢失当前位置 | 任务链断裂 / 导航成本 |
7 | 看完作品没有"下一步" | 三条边（同模型/同题/同提示词）正是图谱价值所在，却只作为区块被动陈列 | goal-gradient 断点 |
8 | 版本更新只在 timeline tab 里 | 访客不知道"这作品更新过 3 次"，作者的回访动机被浪费 | 进度/变化不可见 |
9 | 移动端 iframe 基本不可用（高度、手势） | 主功能在移动设备上不可达 | 响应式基本盘 |
10 | 4 个 tab 与页面区块是两套组织逻辑 | 心智模型冲突：区块是"关于作品的信息"，tab 是"关于作品的档案"，用户不知道该往哪儿找 | **一致性**（同一空间只该有一套组织原则） |

## 3. 目标结构

```
┌──────────────── 左：作品本体（sticky，≈62%）────────┬──── 右：信息面板（≈38%）────┐
│  [ 预览 iframe / 下载卡 / 外链卡 ]                    │  标题 · 作者 · 时间              │
│  ▲ 常驻浮标：给个分 ★☆☆☆☆（键盘 1–5）                │  模型署名（可点，新标签）        │
│  底部：全屏 / 重开 / 版本 n                          │  评分 + 票数 + 样本档            │
│                                                      │  标签（含 type/game）            │
│                                                      │  下载 / 打开外链 / 编辑          │
│                                                      │  「更新过 3 次，最新：修音效」    │
└──────────────────────────────────────────────────────┴──────────────────────────────────┘
        ↓ 以下单列，按"读者问题的顺序"排，不再并列堆叠
   ① 它是什么            描述 + 第一轮提示词（原文可折叠）
   ② 怎么做出来的 ★      会话日志摘要 + 展开查看（本站独特证据，从 tab 提到版面）
   ③ 和别的答案比        严格复现（同提示词）｜同命题发挥（同题）—— 两种形态明确区分
   ④ 继续逛              三选一出口：同模型其他作品 / 同题其他模型 / 同提示词
   ⑤ 讨论区              评论（默认折叠计数，点开才加载）
   ▸ 档案（作者/管理员）  版本时间线 · session 原始文件 · 删除 —— 收进抽屉
```

### 三条硬规则

1. **作品本体永远在首屏且不滚走**（sticky 预览）：详情页的第一任务是"让它跑起来"。
2. **三种"比较"必须形态不同**：严格复现（同提示词）用**并排对照**样式；同题作品用**榜单**样式；相关推荐用**卡片流**样式。同形即同类，是这页现在最大的信息事故。
3. **档案与访客内容分层**：timeline / 原始日志 / 破坏性操作收进「档案」抽屉；访客只看到一行"更新过 N 次"的摘要（有信息量、无噪音）。

### 规则 1 的补完：信息卡可收起（决策人实测后追加）

「预览是主角」不是恒真的 —— 有时作者就是要**看信息**，有时就是要**只看作品**。所以两栏不是固定答案，
**可切换才是**：

- 事实卡右上角「收起 ›」→ 预览整宽（实测 **830px → 1212px**），右侧留一条**细轨**（`信息` + 分数 + 竖排标题）
- 快捷键 `I` 切换；**在输入框里打字不误触**（有断言锁住）
- 状态写 `localStorage`，**跨刷新记住**（每次进来都要重按一遍是失礼）
- 窄屏收起后细轨变横向按钮并**排在预览之前** —— 藏掉恢复入口等于自造死角

## 4. 认知与设计依据（为什么这样排）

- **问题顺序 = 阅读顺序**（信息寻路）：`这是什么 → 能玩吗 → 谁做的 → 怎么做的 → 比别人怎样 → 下一步`。现在的顺序把"谁做的"放最前（hero）、"能玩吗"和"怎么做的"分列两处，是**按数据模型排**而不是按问题排。
- **执行-评估循环**（Norman）：评分浮标常驻预览右上角 = 玩完立刻能反馈，不必回头找入口；键盘 1–5 给熟练用户效率通道。
- **认知负荷**：右栏承担"事实卡"（静态、可扫），主列承担"叙事"（描述→过程→比较），两者不同时争夺注意力。
- **目标梯度**：④「继续逛」把图谱的三条边变成**明确的下一步**，而不是被动陈列的区块。
- **受众分离**：管理员/作者需要的档案能力与访客需要的理解路径分开，互不污染。
- **格式塔邻近**：版本摘要紧贴"更新过 N 次"文本，而不是躲在另一个 tab 里。

## 5. 明确不做什么

| 不做 | 理由 |
|---|---|
| 会话日志默认展开 | 体积大（单文件可到数百 KB），且多数访客只想知道"是真做的" → 摘要 + 按需展开 |
| 给匿名访客看 agent 通道/原始日志文件 | 受众分离；那是作者与管理员的证据 |
| AI 生成"作品总结" | v2.0 零 LLM 调用是既定约束（落地计划 §2），且总结会污染"作者自己说的话" |
| 评论无限瀑布 | 论坛是独立板块，详情页只做计数 + 跳转 |
| 把"相关推荐"改成算法推荐 | 现有随机 + 换一批已够用；上排序需要特征工程，另案 |
| 侧滑快速预览（第 3 期再做） | 需要新的 mini-detail 端点或复用大响应，收益不如先把版面立住 |

| 期 | 内容 | 风险 |
|---|---|---|
**1** | 两栏版面（sticky 预览 + 右信息卡）、评分浮标常驻、**三种比较改名并分节**（严格复现 / 同命题发挥 / 随便逛逛）、更新摘要行 | 低：只动模板与样式，不改数据与接口 |

### 第 3 期落地（2026-09-02）

- **`GET /peek/{kind}/{ident}`**：三种实体共用一个紧凑形状（含 `full_path`，前端不自己拼 URL）；
  分数走 §25.1 **同一个函数**，不另写一套算法。
- **`PeekDrawer.vue`**：右侧滑入抽屉。打开时**不卸载本页**（实测 URL 不变、事实卡仍在），
  焦点入抽屉 + `aria-modal` + Esc/遮罩关闭；两条出路（在本页打开 / 新标签）。
- **◱ 与 → 的区分**：就地预览与直接导航必须有不同视觉，否则用户无法预期点击的后果。
- **iframe 懒挂载**：进视口前 200px 才挂。**这里我引入过一个回归**：第一版在 `onMounted` 里
  `observe(stageEl)`，但那一刻 `demo` 还在请求、`.dv-stage` 不存在 → observer 从未挂上、
  **预览永久空白**；被断言 `iframe: true` 当场抓到，改为 `watch(stageEl)`。


### 第 2 期落地（2026-09-02）：tab 结构整体废除

原计划做"档案抽屉"，动手时发现**更根本的问题是诊断 #10**：tab 与正文是两套组织逻辑，
读者不知道该往哪儿找。所以直接把 tab 全删，统一成一条正文阅读序：

```
预览 + 事实卡 → ① 它是什么 → ② 怎么做出来的 → ③ 讨论 → 比较三节 → 随便逛逛
```

- **② 怎么做出来的**：会话日志与版本时间线改为**原生 `<details>`**（键盘可达、零 JS 状态、展开即读）——
  本站最独特的证据（真实生成轨迹）从第三个 tab 提到正文；空态写明"这件作品没留下过程记录"。
- **③ 讨论**：直接占版面，不再是一个 tab。
- 事实卡里的「看版本 →」= 跳到对应 disclosure 并展开（断言：`y 0 → 1078`、`open=true`）。
- 评分分布图修复：柱宽 **6px → 24px**、柱高上限提为 prop（`distMax`，窄栏 34），不用 `!important` 掰内联样式。

**验证**：CDP 断言 6/6（tab 数=0、时间线可展开并滚动、讨论成为正文区块、会话日志列出真实文件并渲染）。
其中"会话日志"一条最初被跳过 —— 仿真库 `session_logs` 为 0（当初只灌行数据没搬文件），
补一个样例日志进 `storage/demos/<slug>/sessions/` 后才真正走通（目录是 **demos** 复数，我先写错成 demo）。

## 7. 验收标准

1. 首屏内**预览与评分入口同时可见**（1440×900 与 390×844 各测一次）
2. 三种"比较"在视觉上可区分（不靠读标题）
3. 普通访客看不到编辑/删除/原始日志；作者与管理员一眼找到
4. 从详情页跳到模型页**不丢当前位置**（新标签或侧滑）
5. 评分点击路径 ≤ 1 次交互（常驻浮标），键盘 1–5 可用

## 9. 动效规范（全站适用，依据 stylekit.top/styles/neo-brutalist）

决策人指出"动效有点诡异"并给出参考站。对照该站的**四法则**，我的动效违反了三条：

| 法则 | 要求 | 我原来的错 |
|---|---|---|
**01 Physical Crushing** | `active` 位移 **= 阴影偏移**，阴影清零（压进表面） | 只有 hover 位移 2px，按下没有 crush |
**02 Brutal Snap** | 背景**硬切**，**禁止 opacity 淡入** | 收起/展开用了 opacity 淡入 → 飘、诡异 |
**03 Zero Rounding Easing** | 一律 **150ms ease-out**，禁止弹性回弹 | 用了 `cubic-bezier(0.2,0.9,0.3,1)`（带 overshoot）+ 200ms `ease` |
**04 Heavy Focus** | hover 时阴影**变大且换彩色** | hover 只位移，阴影不变 |

落地为 CSS 令牌（`style.css` 末尾的动效层）：

```css
--b-dur: 150ms;  --b-ease: cubic-bezier(0,0,0.2,1);
--b-shadow: 4px 4px 0 0 var(--ink);   --b-shadow-hot: 8px 8px 0 0 var(--red);
```

- 面板出现改用**盖章落位**（`scale(1.06) rotate(-1.2deg) → 0.985 → 1`，150ms，**无淡入**）—— 与本站"印章"语汇一致
- 卡片 hover：`translate(-2px,-2px)` + 阴影升到 8px 且换彩色；active：`translate(4px,4px)` + 阴影清零
- 全部包在 `prefers-reduced-motion` 里退回无动效

## 10. 评分卡美学（第二轮）

问题：星标在右上、大数字在它**下面偏左**，中间空一块 —— 因为数字被关在 `.rating-meta` 这个网格里。
手法：`.dv-facts .rating-meta { display: contents }`，让 avg / sub / 图表 **直接成为卡片的网格项**，
于是「大数字 + 星标」同行、其余满宽左对齐；卡片高度 276 → **237px**。

色阶修正：5 分原用**纯黑**（整张卡最重的元素成了一个数据条，且黑是本站结构色，读起来是死色）
→ 改为 1 红 / 2 纸白 / 3 黄 / 4 薄荷 / **5 青绿**，"最高档"用彩色而不是结构色。

## 11. 一处我自己引入的回归（必须记）

iframe 懒挂载第一版写在 `onMounted` 里 `observe(stageEl)` —— 但那一刻 `demo` 还在请求、
`.dv-stage` **根本不存在**，observer 从未挂上，**预览永久空白**。断言 `iframe: true` 直接抓到。
改为 `watch(stageEl)` 在元素出现后再挂。
**教训**：懒加载/观察器类的代码，"元素何时存在"必须显式验证，不能假设挂载即就绪。
