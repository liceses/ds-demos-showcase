# 上传页重设计（v2 · 界面工程）

日期：2026-08-31 ｜ 依据：`落地计划.md` §4.2（两段式）+ §4.5（tier）+ Q2 决议 + D5（组盒边界）
本文是**设计与取舍的记录**，实现见 `frontend/src/views/UploadView.vue`。

---

## 1. 现状诊断（按代码事实，不靠感觉）

改版前的页面是**一张长表单 + 一个装着 160 个值的抽屉**，实测特征：

| 观察 | 出处 | 触发的原理问题 |
|---|---|---|
| 12 个字段一次全暴露，必答（模型）与可选（视频）视觉权重相同 | 原 template 平铺 | **Hick–Fitts**：选择反应时 ∝ log(选项数)；目标越小越慢 |
| 标签抽屉里 160+ 值靠滚动浏览 | `TagPicker` 全词表 | **认知负荷（Sweller）**：intrinsic（选对值）+ extraneous（在哪找、要不要选）叠加 |
| 校验全部在点「上传」之后 | `submit()` 里一串 if | **错误控制（Reason/Norman）**：事后报错 = 让用户承担发现成本；约束应前移 |
| 唯一反馈是「已选 N」 | `tag-drawer-count` | **无进度表征**：goal-gradient（Kivetz）要求"离目标还有多远"可见 |
| 建议包藏在抽屉内部 | `tag-drawer-head` | **非注意盲视**：不主动出现就等于不存在 |
| `upload_code`／幂等键／强制上传 与作者字段混排 | 原 template | **语义污染**：不同受众（作者/agent/管理员）共用一层视觉 |
| 成功后只有「查看 Demo」 | `notice-success` | **目标梯度断掉**：没有下一步（补提示词/补标签/看题） |

一句话：**旧页面把"数据库需要哪些列"当成界面来画了。**

---

## 2. 重新设计的三条公理

1. **界面 = 状态机的投影**（CS）：作者的心智任务是「声明一个作品的来历」，拆成互不干扰的三个子问题；一步只解决一个，步内不留必填盲区。
2. **元数据要有出处**（信息科学）：作者声明的、系统推导的、不确定的，三者必须在界面上可区分 —— 否则词表会被"猜的"污染（这正是 `type:demo` 吞 46% 与 `ds-unknown` 吞 63% 的成因）。
3. **不确定是合法输入**（认知心理学）：人在记忆不可靠时会**编一个看起来合理的答案**（confidence 高的错误）。所以"不知道"必须有一条与"知道"**同等显眼、一次点击**的路径，并顺手留下证据（`model_hint`）。

## 3. 新结构

```
┌──────────────────────────────────────────────┬──────────────────┐
│ 步骤条  ① 作品是什么   ② 谁做的   ③ 说清楚    │  完成度仪表盘     │
│ ───────────────────────────────────────────── │  必答 3 项        │
│  当前步的字段（≤5 组，相关字段同卡）           │  建议 2 项        │
│                                              │  可选 N 项        │
│  [上一步]                     [下一步 →]      │  （点击直达对应步）│
└──────────────────────────────────────────────┴──────────────────┘
```

### 步骤 ① 作品是什么
- 类型用**三张大卡**（radio card）而不是 `<select>`：选项全可见（省一次展开的记忆负担）、命中区域大（Fitts）
- **文件/链接输入紧跟类型**并在同一卡内 —— 二者强耦合，格式塔邻近性（proximity）表达依赖关系
- 类型相关校验就地即时反馈（link 缺 URL / 未选文件），不等提交

### 步骤 ② 哪个模型做的（必答）
一条**决策树式**的界面，把 Q2 的四档断言强度变成四个可见出口：

```
精确型号  [搜索框]  [常用型号 chips]        ← 主路径
────────────────────────────────────────────
知道厂商，不确定型号  →  选厂商（列表来自词表 group，不客户端重算 slug）
完全不知道            →  model:unspecified
网传灰测、未经证实    →  model:ds-unknown
```
- 选了任一兜底 → **就地**追问 `model_hint`（"为什么不确定"），并说明"日后会被批量归位" —— 不确定被转化为**可收敛的数据**而不是垃圾桶
- 厂商列表**只列词表里真有 `<vendor>-unknown` 值的厂商**：避免客户端复刻服务端的 slugify 规则造成漂移（两处规则必然漂移，运维 §15）

### 步骤 ③ 说清楚 + 补充
- 标题/描述/提示词（挑战上下文在这里，因为原题面直接喂 prompt 与标题）
- **建议包主动呈现**（不再藏在抽屉里）：一行 chips + 「全部收下」，每条悬浮显示依据与置信 —— **provenance 可见**
- 封面/视频归入「呈现」组；`upload_code`/幂等键/强制上传/编辑项 收进 **`高级（多数人不需碰）`** 折叠 —— 受众分离
- 「挑其他标签」仍是全词表编辑器（TagPicker 抽屉）：需要完全控制的人有门，普通人不必进去

### 提交前 · 核对页
摘要视图（声明了什么、系统补了什么、还缺什么）→ 再提交。
理由：让作者在**信息最完整的时刻**审一次，是错误拦截成本最低的位置；同时把"提交"这个动作从"表单行为"升级为"发布确认"。

## 4. 认知/可用性细节清单

| 手法 | 实现 |
|---|---|
| 进度可见（goal-gradient） | 仪表盘按必答/建议/可选三层计数；起点非零（挑战或标签推导会让第 1 分钟就有进展） |
| 一步一问（Miller 7±2） | 每步可见控件组 ≤5 |
| 错误前移 | 步内即时校验 + 「下一步」在必答未满足时**禁用并说明原因**，而不是提交后弹错 |
| 防误操作 | 脏状态下离开页面二次确认（beforeunload）；提交中禁用重复点击（原已具备） |
| 记忆卸载 | 兜底出口写全三条值名，作者不必记住 `unspecified` 怎么拼 |
| 容错可回退 | 步骤可任意来回，状态不丢（单组件持有全部字段） |
| 无障碍 | `fieldset/legend`、步骤条 `aria-current`、切步后焦点移到该步首个控件、跟随 `prefers-reduced-motion` |
| 一致语汇 | 组盒/徽章/chip 复用既有设计令牌，不新建视觉家族（D5：面板级才组盒） |

## 5. 明确不做（以及为什么）

- **不做整页"表单分屏到 8 步"**：步数过多会切断目标感（每步都要重建上下文），三到四步是常见甜点区；细碎字段靠分组与折叠解决，不靠分页。
- **不在客户端重算 slug / 归一化**：服务端单一来源，前端只消费词表。
- **不把建议包变成"自动填"**：一律作者点头才收（provenance：建议 ≠ 声明）。
- **不给匿名作者看 agent 通道说明**：`AI_AGENT_GUIDE` 是给机器的，页脚只留一条链接。

## 6. 调优轮（决策人反馈：有些操作不能取消 / 完成度再高一点 / 加可玩性）

### 6.1 可取消：每个"决定"都配一个"改主意"

原则：**用户的每个动作都要可逆，除非它本来就不可逆（那时必须二次确认）**。

| 原本会卡住的地方 | 补的出口 |
|---|---|
| 原生 `<input type=file>` 选错清不掉（置 null 在部分浏览器无效） | `:key` 重挂 + 已选文件行 ✕（含文件名与体积） |
| 模型选错只能换值、不能取消 | chip 内 ✕ + 「改主意」（同时清 `model_hint`） |
| 从题目页带 `?task=` 进来就被挂题绑架 | 「✕ 不挑战这题了」→ 摘横幅、提交不带 `task`、自动预填的标题一并清掉 |
| 建议包点「不用了」后永久消失 | 「↺ 重新看看标签建议」（静默永久隐藏是设计失礼） |
| 封面选了不能撤 | 预览角标 ✕ |
| 厂商列表展开后收不回 | ▴ 收起 |
| 整页填错想重来 | 「清空重来」= 本页唯一破坏性动作 → 二次确认 + **重生幂等键**（不复用旧实验编号） |
| 成功后页面还停在上次的输入上 | 「＋ 再传一个」把向导清干净复用 |

并把**门禁错误与服务器错误彻底分开**（`stepError` / `error`）：前者随补全自动消失，后者（409 重复等）保留到下次提交 —— 否则用户会看到"我明明修了，红字还在"。

### 6.2 完成度：把"还差什么"变成可操作对象

- 仪表盘每项带 `✓/·` 状态点；必填未成用红字，但**不只靠颜色**（符号 + 加粗，色盲可用）
- 步内问题从"藏在禁用按钮"升级为**就地列出**
- 字段**实时字数计数器**（标题/描述/提示词）+ 一句"为什么值得写"（标题=搜索入口，提示词=别人复刻你实验的凭据）
- 链接类型**即时**格式校验（红边 + `aria-invalid` + 文案切换），不等提交
- 摘要页每行加「改」直达对应步 —— 核对不该是重填的别名
- 禁用的提交按钮带 `title` 说明**缺哪几项**（禁用而不解释＝看起来像坏了）
- a11y 补齐：进度条 `role=progressbar`、步内错误 `role=alert`+`aria-live`、类型卡 `aria-pressed`、步骤条 `aria-current="step"`

### 6.3 可玩性：只做"有信息量的趣味"

原则：**每个趣味点都必须同时给用户或系统一点真东西，且可一键关。**

| 趣味点 | 真价值 | 数据来源 |
|---|---|---|
| **称号**（草稿→半成品→说得清→认真的人→民间科研杰作） | 把百分比翻译成人话，制造"再补两项"的收尾动机（goal-gradient） | 完成度计数（真实） |
| **盖章动画**（选模型时「已登记」） | 给"署名"这个动作一点仪式感；`prefers-reduced-motion` 下静态 | 事件驱动 |
| **旁白**（如"诚实比准确稀有""系统查了词表，你签了字"） | 每次都在解释**刚发生的动作意味着什么**；💬 一键关（存 localStorage）；同一事件不重复念 | 事件驱动，非随机鸡汤 |
| **站内战绩条**（选中模型：N 件作品 · 平均社区分） | 让作者知道"我选的模型在这站什么水平"，直接影响要不要挂题 | `GET /models/{slug}`（防抖 260ms；拉不到就静默退场） |
| **🎲 抽一题** | 把「挑战」闭环真接上：没灵感时给一道题 | `GET /tasks`（优先有作品的题）；**只跳转，不自动挂题** |
| **实验编号 `EXP-XXXXXX`** | 截图/回报 bug 时能指认这一次上传 | 幂等键末 6 位，**不改后端语义**（纯读法） |

刻意**不做**：音效、随机奖励、无意义进度动画、把建议变成自动填 —— 只消耗注意力，不给作者任何东西。

## 7. 决策人实测后的两条修正（2026-08-31）

### 7.1 「抽一题跳走后已填内容丢失」

**根因**：`抽一题` 是 `RouterLink`，站内跳转会**卸载 UploadView**，组件内所有 `ref` 随之消失 —— 不是跳转逻辑写错，是 SPA 的生命周期本性。任何"页内跳出去看参考资料"的动作都有这个风险。

**两层修法**：

1. **就近**：抽题链接改 `target="_blank" rel="noopener"` —— 看题面是**参考动作**，不该以离开表单为代价；
2. **兜底**：加**草稿持久化**（`localStorage['upload.draft.v1']`，字段级防抖 500ms），任何原因的离开（刷新、误关、误点外链）都能恢复。

草稿的四个设计决定：

| 决定 | 理由 |
|---|---|
| **只探测、不自动覆盖**（顶部黄条「继续填 / 丢弃」） | 误恢复比误清空更难被察觉 —— 作者可能带着上一次的模型署名继续填，静默恢复的代价更高 |
| 连**幂等键**一起存 | 若中途真提交过一次，回来重试仍走同一 key，不会被当成新作品 |
| 有挑战预填时**不抢标题** | 作者填过的东西优先于系统预填 |
| 编辑态**不写草稿**；成功后**立即清草稿** | 编辑的是某件作品，不该污染创建态；发布成功后下次该是白纸 |

诚实边界：**`File` 对象存不进 localStorage**，所以文件与封面不恢复，草稿条上直接写明「文件与封面需重新选」。

> **为什么不用 `keepAlive`**：把 UploadView 加进缓存列表看似更省事，但它会在 `?slug=`（编辑）与 `?task=`（挑战）之间复用同一实例，而 `onMounted` 不再执行 —— 结果是**带着上一件作品的表单去编辑另一件**，那是比"内容丢失"严重得多的正确性 bug。缓存省的是内存，赔的是数据归属。

### 7.2 摘要页「改」的位置

原实现把它放在第三列，且**只有 3 行有、3 行没有** → 右边缘参差不齐，看着像漏标。改为数据驱动（`reviewRows`）：**六行统一右对齐、同一条基线**，默认 `opacity .45`、行悬停到 1（不抢读但可发现）。同时把"值为空"的行淡化（`.empty`），核对时一眼看出哪项还没填。

### 7.3 验证与待复测

`vue-tsc -b` 0、`vite build` 0、pytest 97 例通过（前端改动，后端零变化）。主观手感仍需决策人在 `:5180/upload` 复测，这次重点三件事：① 抽题后回来内容是否还在 ② 刷新后草稿条是否出现且不打扰 ③ 摘要行「改」是否顺眼。
