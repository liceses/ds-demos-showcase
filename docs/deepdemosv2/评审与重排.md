## 二、文档打架三处 —— 裁决

| # | 冲突 | 裁决 | 依据 |
|---|---|---|---|
| **R1** | Model 状态机：治理文档 `discovered→candidate→verified→active→deprecated→archived` vs 落地计划 `candidate\|active\|unverified\|deprecated` | **保留代码四值** | `unverified` 正是「灰测未确认」，是 idea 2 揭晓机制的资产；六态在当前无 discovered/archived 数据来源前是空转字段 |
| **R2** | `source` 枚举：治理文档 §38 六值 `user\|admin\|ai\|inferred\|external\|imported` + confidence vs 落地计划 `rule\|user\|agent` | **采用治理文档六值**，并**并入 `rule` 语义为 `inferred`** | 六值是唯一明写处；建表时一并落 `confidence REAL`（§十六 三级置信度的落点） |
| **R3** | Task 是否必须支持 `split` | **押后**，只留 `merge_task` | 全站 Task 数 = 0，连「粗 Task」都没有，split 无对象；文档标注为「Task 破 50 后重估」 |
| **R4** | astra 橱窗是否放行 `/models`、`/tasks` | **不放行，橱窗代码整体不动**（2026-08-31 决策人拍板） | 核实：astra 是独立 mini-SPA（`main-astra` + `AstraWorksView/AstraWorkView`），不用 `DemoCard/ModelChips`、站内链接只有 `/`、`/about`、`/demo/:slug` → 无死链；`model:` 标签历史上就对外可见，序列化 `models[]` 非新增泄露面 |
| **R5** | Run 收编是否切断 `tag=rounds:` 写入 | **不切**：标签仍是写入面，列是「可计算的那一份」，双读 | `?tag=rounds:3-10` 是已发布 agent 契约（`AI_AGENT_GUIDE §6`）；单方面停写标签会让新作品在旧参数下**静默失踪**，比双轨更糟 |
| **R6** | Q2「强制 ≥1 model」怎么落地 | **强制与三档兜底同时上**：`family`（知厂商不知型号 `<vendor>-unknown`）/ `unknown`（`unspecified`）/ `guess`（`ds-unknown`，与灰测资产同轨），并收 `model_hint` 证据 | 只强制不给正门 = 逼人和 agent 编型号，比空着更脏；兜底必须是**真实 Tag 值 + 真实实体**（`model` 是 fixed 键，不进词表就是假门）；D 与 B/C 分开才保住 396 个灰测作品的「揭晓」资产。详见 `落地计划.md` §13、`API_CONTRACT.md` §15 |
| **R7** | v2 新实体是否各占一个顶栏导航位 | **不占**。定「导航位不随实体增长」：新增一级对象一律从 `/tags`「探索」下钻（D3 已落地） | 我上一轮把 Explore 拆成 `/models` + `/tasks` 两个列表页并各加导航位，顶栏从 5 涨到 7 项被决策人指出；正确做法是**一个入口 + 三个下钻页**。规则写进 `API_CONTRACT.md` §16 防复发 |
| **R8** | slug 可否含非 ASCII | **不可**：展示用中文、URL 用 ASCII slug（中文题面退化 `task-N`） | 仿真「成题」实测生成 `/tasks/仿真题-坦克-科幻-幻坦`，与 Q4 相反、分享链接全是百分号编码；中文厂商名族节点还会全员撞 `vendor-unknown` 互相改指向。回归锁 `test_cjk_titles_and_vendors_get_ascii_slugs` |
| **R9** | 归属工作台该不该承担"自动归位" | **不该**。分工：单件判断走工作台（人看 `model_hint` 证据），**整批揭晓走 `merge_model`**（一次迁完全部引用） | 仿真实测规则预填命中仅 **2/82 ≈ 2.4%** —— 历史数据没有 `model_hint`、提示词里也少写型号名。若不做这条分工，396 个灰测作品会变成"看着能自动、其实要手点 396 次"的摆设；而「ds-unknown 其实就是某型号」本来就是单次全局声明，`merge_model` 一次搞定 |
| **R10** | `type:demo` 拆分要不要自动改标签 | **不自动**：规则 → 候选 → 人工批准（预览 / 入队 / 批准三段），管理面板默认置信度 **0.8** | 真实语料校准出置信度分层：≥85% 基本可信、72~84% 有明确误判（博客站因"物理"二字被判成 simulation）。走自动改会在 285 件里错 30~40 件且不可见；三段式让管理员先看质量再入队，批准后仍留审计 |
| **R11** | 巡检面板要不要给每个检查项都配「一键处理」按钮 | **不配**。`can_queue` 严格等于「该检查项存在不依赖猜测的自动补救」（只有 `type_missing`/`type_multi` 两项），其余一律 422 | 「缺提示词」「固定值缺介绍」这类缺口机器补不出来；给个按钮只会产出垃圾候选并让管理员误以为点了就完事。**假动作比没动作更坏** —— 面板上明确分成「可处理」与「只能人工看」两栏，读数本身有价值 |
| **R12** | 上传页要不要做整页分步向导 | **要做**（推翻我 §4.2 上一轮「收益递减、不做」的判断）。三到四步是甜点区，**不做 8 步碎页** | 我那个结论的隐含前提是「进度已经可见」，而实际页面既没有进度表征、又让必答项与可选项同权重、还把建议包塞进抽屉（≈没人看见，非注意盲视）。补上**完成度仪表盘 + 步内门禁 + 主动呈现建议**后分步才真正削减外在认知负荷。教训：**否定一个设计前，先承认自己漏了它所依赖的前提**。逐条原理映射见 `上传页重设计.md` |

## 三、实测新增细节（原文档未覆盖，开工时一并处理）

1. **「候选不外泄」口径不一致**（实测）：`list_models` 缺省只出 `active+unverified` ✅，但 **`serialize_demo` 的 `models[]` 不过滤任何状态** —— `candidate` 实体会原样出现在公开 demo 详情上（前端 pending 徽章兜着）。
   → **定稿规则**：序列化层过滤 `deprecated`（已退役不该出现在新页面），**保留 `candidate` + 前端 pending 徽章**（用户自己选的模型被藏掉更奇怪）。在 B1.5 一并落实并补测试。
2. **slug 归一会吃掉分隔符**（实测）：`_slugify_unique` 走 `normalize`，`dsv4-flash` → slug **`dsv4flash`**；而历史自由值标签里本就有 `dsv4flash` → normalize 结果相同 → 新实体 slug 变 `dsv4flash-1`。
   → 线上 99 个 model 值迁移时此类冲突会真实发生。**B1.5 必加测试项**：slug 唯一性 × 别名撞名。
3. **测试断言缺口**：文档点名的「同一 model 字符串重复上传必须复用不新建」—— 现有 `test_models_v2.py` 只断言了 **prompt 不重复增长**，**未断言 Model 实体复用**。约 5 行，B1.5 补。

## 六、聚类前置条件（idea 1 的调参门槛，避免误簇）

TF-IDF 中文二元组 + 余弦在 ~240 条 prompt 上跑连通分量，阈值一松即成片弱相似误簇。**进建议列表的硬条件**：

```
score ≥ 0.35  且  簇内 ≥ 3 个 demo  且  覆盖 ≥ 2 个不同 Model 实体
```

阈值必须在**线上真实 prompt 语料快照**上调，不接受本地小库调参结果。

### 标定结果（2026-08-31 线上 610 作品 / 235 条提示词，已执行）

| 档位 | 实测 |
|---|---|
| 同句（exact） | 216 个去重提示词 → **11 个同句簇，其中 8 个跨模型**（「0831 科幻坦克」6 作品横跨 HY4 / ds-unknown / dsv4-flash-vision / glm5.3flash / qwen3.8flashNext） |
| `th=0.35` | 10 个 ≥3 簇（45 作品、9 跨模型） |
| `th=0.25` | 11 个簇——只多 1 个，且**开始混入误簇**（「反向复合弩 / 双叉臂悬挂运动学台架」主题相近但不同题） |
| `th=0.20 / 0.15` | 12 / 15 个簇，增量基本是噪声 |

**结论与本节初稿的两点修正**：

1. `0.35` 判为正确档位（更低即掺水），维持不变。
2. **新增 `exact` 档**：同句簇不需要任何相似度判断、质量最高，故**不套用「≥3 作品 + ≥2 模型」门槛，放宽为 ≥2 作品即可**（初稿把两档混在一起，会把「蒙娜丽莎」这类 2 作品跨模型的好题直接挡在门外）。`similar` 档维持 `≥3 作品 + ≥2 模型 + ≥0.35`。
3. 落地位置：`cluster_service.prompt_clusters()`（两档输出 + `covered` 标记 + 60s 缓存、写路径失效）。
