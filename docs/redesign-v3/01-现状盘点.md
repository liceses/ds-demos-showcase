## 6. 状态管理与运行时行为

- **Pinia 仅 4 store 且极薄**（auth 54 / ui 46 / tags 33 / notifications 66 物理行）：auth=用户+登录注册登出；ui=toast+confirm 服务（Promise 化 confirm 设计不错）；tags=标签选择共享态（4 引用）；notifications=通知轮询态（2 引用）。**没有全局 demo/列表缓存 store**——各视图自拉自管。
- **KeepAlive 机制**（App.vue L18-27）：include 8 个页面按 route.name 复用；pageKey 只用 path 不用 fullPath（注释详述了"fullPath 当 key 导致排序/筛选整页重挂、滚动弹顶"的历史教训）；`meta.remountOnQuery` 是 /upload 的身份特例。机制自洽但认知成本高，新视图必须理解三套 key 规则。
- **视图自拉数据**：24 个路由视图里 20 个直接 `api.*` + 本地 ref/computed 组装；URL query 同步在 DemosView 等列表页各自实现（`useListPage` 37 行 composable 只覆盖 4 处）。
- `stores/ui.ts` 的 toast 无上限堆积控制（仅 3.2s 定时移除）——连续触发会叠层，属边界事实。
