### 1.4 吸收清单（本节唯一输出，按对账表仲裁排序）

1. **hover 物理统一（R6，最高优先）**——现网按钮 hover 压平 → 参考物理「hover 增影抬起、active 才压平」；v2 动效规范 §3 的 `.btn` 例外条款（「轻压 2px，一致性优先于教条」）**自 v3.1 起作废**（用户指定参考优先），见 §2.2。
2. **50% 单一缩放律（R1/R2）**——移动端数值 ≈ 桌面 50%：边框 2/4px、阴影三档 2/4-4/8-6/12，全站一条缩放律，顺带收敛两套断点并存，见 §2.2/§4.5。
3. **颜色 0ms 硬切（R7）**——transition 剥离 background/color/border-color（现行统一收口含颜色 150ms，需改），见 §2.2/§2.3。
4. **引入 `brutal-march`**——用于「进行中/排队/上传中」语汇（进度条边、审核中徽章、live 徽标），替代现行 `live-pulse`（opacity 呼吸，L2717，微违反法则 02）。
5. **引入 `brutal-stamp` 强档**——仅用于「大物件登场」编排（面板首挂/成功页/成就章），与现行 150ms 微档分级并存；**列表项不做逐项入场**（提炼文档落地注意），见 §2.3。
6. **色板仲裁落地**——默认主题（纸白）保留现网 playful 色板基因；**参考色板（#ff006e/#ccff00/#00d9ff/#ff9500）并入墨黑主题做暗色优化**（03 §11.2 仲裁，独立 acid 主题取消）；大面积底色用低饱和变体，见 §3.3/§3.4。
7. **旋转限制（R8）**——旋转是保留的个性基因但降为受控：仅卡片/徽章允许 ±1~2°，**列表卡片禁旋转**（信息密度），见 §2.2。
8. **禁止项与自检清单机器化**——合并 playful 与 plain 两份清单为统一禁止模式表（补 border-gray-\*），stylelint 守护 + 测试断言，见 §4.7。
9. **不采纳项**：参考站字体族（Albert Sans/Playfair——本站 Inter+JBM+中文栈是既定决策）、渐变文字示例、`neo-brutalist-fade-in` opacity 淡入示例（法则 02 已裁决禁止，参考站示例是「给 AI 的通用模板」，本站标准更高）；荧光粉/酸性黄**不再列为不采纳**——已改判为墨黑主题的强调色系（见第 6 条）。

## 2. 视觉规范 v3.2：「保留并完善」的具体口径

### 2.1 不变项（灵魂清单，动不得）

- 五强调色（现网色板基因，角色名见 §3.4）；
- 纯黑边框（桌面 4px/移动 2px，R1）、硬偏移阴影、rounded-none（`border-radius` 全文件 0 声明）；
- 印章/盖章语汇、`::selection` 红底；
- **贴纸旋转（v3.2 收窄为装饰层，R8）**：常驻倾斜仅限印章/贴纸/徽章/非文字装饰块（EntityStamp、`*stamp`/`*badge` 族、公告图钉、瞄一眼贴纸）；**一切文字承载元素静止态 rotate=0**（列表卡/信息卡/表单/按钮/榜单行/admin 面板）——个性由印章语汇/贴纸/硬影/配色承担，**卡片不承担**（用户拍板：斜排文本增加阅读成本 + 眩晕敏感）；瞬时旋转仅存两处：入场 stamp 轨迹（-6°→1°→0）与按压压平（可叠 ±1° 微倾）；
- Inter + JetBrains Mono 字体族与 `font-black uppercase` 标题法；
- 论坛牛皮纸作用域子主题（§3.3 论证不升全站主题）。

### 2.3 动效规范 v3.1（双速制 + march 语汇 + 全局闸）

v2 四法则全部继承（`docs/deepdemosv2/动效规范.md` 是现行有效文档，本节只做增量）。**时长表（采纳提炼文档，v3.1 生效）**：

| 交互 | 时长 | 缓动 | 现网差异 |
|---|---|---|---|
| hover 位移/阴影 | 150ms | ease-out | ✓ 已是 150ms |
| active 按压 | **瞬间** | — | 需加 `:active{transition-duration:0ms}`（现按压缩放也被 150ms 动画拖慢） |
| 颜色瞬切 | **0ms 硬切** | — | 统一收口（L5958）把 background/color 放进 150ms，需剥离（R7） |

```css
/* 令牌层（拆至 src/styles/tokens/motion.css，物理前置；--sh-off-*/--border-w 属第 1 层，定义在 primitives.css §3.2，此处只引用） */
:root {
  /* —— 速度档 —— */
  --b-dur: 150ms;                                  /* 交互反馈（法则 03，不变） */
  --b-dur-stage: 350ms;                            /* 编排登场：盖章强档（新增） */
  --b-ease: cubic-bezier(0, 0, 0.2, 1);            /* ease-out，无 overshoot（不变） */
  --b-ease-stamp: cubic-bezier(0.16, 1, 0.3, 1);   /* easeOutExpo，参考标本原曲线（新增） */
  --b-lift: 2px;                                   /* hover 抬起量 = hover 增影量（R6）；≥720 翻 4px */
  --tilt-rest: 0deg;                               /* 静止零倾斜（R8 v3.2）：文字承载元素 resting 基线 */
  --tilt-press: -1deg;                             /* 按压瞬时微倾（仅 :active 可用，150ms 归位） */
  --tilt-deco: -1.5deg;                            /* 装饰常驻专用：印章/贴纸/徽章白名单类（§4.7 守护） */
```

节制红线（新增进动效规范「例外」节）：`b-stamp-hard` 与 `b-march` 都是**编排级**动效——同屏同时只允许一个 march（视觉噪音控制）；`stamp-hard` 只允许路由级登场（页面首挂/向导完成态），**列表项不做逐项入场**（提炼文档落地注意：性能 + 认知负荷——48 张卡一起盖章 = 灾难，逐项 fade-in 同禁）；march 仅装饰边框，`prefers-reduced-motion` 降级由全局闸兜底。

### 2.3.1 动效丰富度 v3.3（转场 + 微交互词汇 + 红线修订；用户拍板「页面内动效再多些，页面间的动效也不要忘记」）

**速度档全表（v3.3 起五档 + 交错步进）**：

| 档 | 令牌 | 值 | 用途 |
|---|---|---|---|
| 交互 | `--b-dur` | 150ms | hover/active/chip pop（不变） |
| **转场（新增）** | `--b-dur-page` | **250ms** | 页面登场 stamp-lite；曲线复用 `--b-ease-stamp` |
| 编排 | `--b-dur-stage` | 350ms | 盖章强档/弹窗（不变） |
| **微交互（新增）** | `--b-dur-shake` | 280ms | 铃铛 shake ±6° 一次 |
| **微交互（新增）** | `--b-dur-count` | 600ms | 数字条 count-up（仅首屏一次，登记豁免项） |
| **交错（新增）** | `--b-stagger` | 30ms | 首屏轻量交错入场步进 |

新增关键帧三个：`b-stamp-lite`（页面登场编排类：opacity 0→1 + scale 1.02→1 + y 8px→0）、`b-rise-in`（轻淡入：8px + 淡入，120ms）、`b-shake`（0→+6°→-6°→+3°→0）。

**R7 修订（v3.3）——白名单分两类**：交互类（hover/active/focus/chip）仍只许 `transform/box-shadow`、颜色 0ms 硬切不变；**编排类（页面转场/交错入场/淡入淡出）允许 `opacity`**。实现口径：opacity 只出现在 animation/转场类上下文，永不进入交互反馈的 transition 属性表。

**节制红线 v3.3 修订**（用户拍板部分覆盖旧红线，裁决如下）：

1. **首屏列表允许轻量交错入场**（覆盖「列表项不做逐项入场」旧条）：≤8 项、位移 8px + 淡入（**非盖章**）、stagger ≤30ms（`--b-stagger`）、总时长 ≤400ms、只动 transform/opacity；「加载更多」新项 = 120ms 轻淡入**无 stagger**（性能护栏保留）。
2. **同屏并发运动 ≤3**（非用户触发同时在动的元素）；用户触发的动效 ≤300ms 内完成（`--b-dur/--b-dur-shake/--b-dur-page` 档内）；`count-up`（600ms）为**登记豁免**（载入播一次，非交互反馈路径）。
3. march ≤1 运行实例 / stamp-hard 仅弹窗 / 静止零倾斜——全部维持；**Tab march 指示条走单实例守卫**：激活 Tab march 时自动暂停 live 徽标、播完恢复（t7 守卫模式推广为 march 协调器）。

**微交互词汇表 → 令牌映射**（03 §12.5 v3.3 逐项落地）：

**页面转场实现范式（可直接抄）**：

```vue

  <!-- Transition 必须包在 KeepAlive 外侧；mode="out-in" 保证旧页先卸再挂新页 -->
  <Transition name="page" mode="out-in">
    <KeepAlive :include="keepAlivePages">
      <component :is="Component" :key="pageKey" />
    </KeepAlive>
  </Transition>
</RouterView>
```

```css
}
```

### 2.4 字体自托管（消灭 Google Fonts 单点）

现状（index.html L11-16）：`fonts.googleapis.com` 外链 Inter(6 weight)+JetBrains Mono(3 weight)，无兜底——国内可达性单点（01 §4.3），且 CSS 阻塞链多一跳。

| 方案 | 做法 | 体积 | 结论 |
|---|---|---|---|
| F1 @fontsource | `@fontsource-variable/inter` + `@fontsource-variable/jetbrains-mono`（latin 子集 woff2，npm 装包进构建） | 两个 variable woff2 ≈ 90-110KB，随 `/assets/` 1y immutable 缓存 | **推荐**。CJK 文字本就走系统字体栈（Noto Sans SC 声明但从未从 Google 加载），自托管只需 latin 子集，成本可控 |
| F2 fontmin 子集化 | 构建期扫描全站用字生成最小字集 | ~15-30KB | 否决：全站文案常变（i18n+funMode），子集漂移维护成本 > 收益 |

配套动作：`index.html` 去掉 Google Fonts 三行；`@font-face` 由 fontsource 包提供；`<link rel="preload" as="font">` 预载标题用 Inter variable；字体族栈不变（`--font-heading/--font-body` 名字与回退链都不动，零组件改动）。

## 3. 多主题 Token 架构（硬需求，专门一节）

### 3.1 四层模型（与 03 §11.1 对齐定稿）

> 本节为 03 §11.1「token 三层架构」的实现侧定稿：层级结构、角色名、层间规则以两文合并口径为准（03 定骨架，本文给取值与 CSS 草案）。

```
第 1 层 形状/尺寸原子（主题恒定，永不随主题变）
        --border-w、阴影偏移三档 --sh-off-sm/md/lg（2/4-4/8-6/12，50% 律）、间距阶、字号阶、
        动效令牌（--b-dur/--b-ease/--b-lift/--sh-off-*…）、--z-*
        ↑ 只被第 3/4 层引用
第 2 层 色板原子（每主题一组，主题差异的第一现场）
        纸白 = 现网五色基因（#ff6b6b/#4ecdc4/#ffe66d/#95e1d3/#f38181 + 纯黑纯白，01 §3.3 已对齐）
        墨黑 = 参考色板暗色优化版（#ff006e/#ccff00/#00d9ff/#ff9500，逐色 AA 重验见 §3.4 矩阵）
        ↑ 只被第 3 层引用
第 3 层 语义 token（角色名跨主题不变——主题=第 2+3 层联合换表）
        面：--paper / --paper-2 / --paper-deep
        文字（三档）：--ink / --ink-soft / --ink-faint
        结构：--line（边框线）/ --shadow-color（阴影色）/ --scrim（遮罩纱色，t7 走查新增：backdrop 字面 rgba 收编，paper .55 / ink .70）
        强调角色：--accent-cta / --accent-ok / --accent-info / --accent-warn / --accent-hot
        字体：--font-sans / --font-mono
        ↑ 只被第 4 层与存量样式引用
第 4 层 组件 token：--btn-bg / --card-shadow / --stamp-rotate …（从语义层取值，禁止直接取色板原子）
```

**铁律三条**：

1. 主题切换只发生在第 2+3 层（每主题一份「色板原子 + 语义」联合换表文件），第 1 层永不变、第 4 层与布局零改动——这正是参考站「暗色模式需要语义 tokens，不要直接把浅色主题反相」（`style-zh-text.txt` L580）的工程化表达，也是 03 §11.1「层级不塌保证」的实现前提：信息层级由尺寸/位置/形状三通道承载，换主题只换颜色表；
2. 下游只准引用上游：**组件层（模板内联与组件 CSS）禁止字面色值**（03 §11.1 立规，本文 §4.7 stylelint 守护）；
3. **遗留别名桥**：`--red/--teal/--yellow/--mint/--coral/--err/--font-heading/--font-body/--border-c/--shadow-c` 等存量名保留定义、逐个指向语义角色（§3.4 表）——6304 行存量引用是最大资产，改名即灾难；别名在 hex/内联收编完成后（P3 末）统一标记 deprecated。

与本文上一版（三层 L1/L2/L3）的关系：旧 L1 拆为层 1+层 2、旧 L2 并入层 3——纯命名重组，CSS 变量求值行为不变，零回归风险。

### 3.5 切换机制工程方案（代码级，全链路；对齐 03 §11.3）

**持久化与预览**：完全复用站内已验证范式（`dsh_lang`/`dsh_fun_mode`：localStorage 持久 + sessionStorage 标签页覆盖 + URL 参数预览）；键值按 §3.3：`dsh_theme` ∈ `system|paper|ink`：

```ts
// src/utils/theme.ts（~55 行，与 funMode.ts/i18n 完全同构）
import { computed, ref, watch } from 'vue'
export type Theme = 'paper' | 'ink'
export type ThemeChoice = Theme | 'system'
const LS_KEY = 'dsh_theme'
const SS_KEY = 'dsh_theme_preview'

// index.html 防闪脚本已先设 data-theme，此处读回对齐（不做二次写）
export const themeChoice = ref<ThemeChoice>((localStorage.getItem(LS_KEY) as ThemeChoice) || 'system')
const preview = ref<Theme | null>((sessionStorage.getItem(SS_KEY) as Theme) || null)

const systemDark = matchMedia('(prefers-color-scheme: dark)')
export const effectiveTheme = computed<Theme>(() => {
  if (preview.value) return preview.value
  if (themeChoice.value !== 'system') return themeChoice.value
  return systemDark.matches ? 'ink' : 'paper'   // 跟随系统：暗偏好→墨黑，否则纸白
})

function apply(t: Theme) {
  document.documentElement.dataset.theme = t
  // 硬切闸：切换瞬间杀掉全站 transition（250ms），防止全页颜色渐变——违反法则 02 的美学事故
  document.documentElement.classList.add('theme-switching')
  setTimeout(() => document.documentElement.classList.remove('theme-switching'), 250)
}
watchEffect(() => apply(effectiveTheme.value))
systemDark.addEventListener('change', () => { if (themeChoice.value === 'system') apply(effectiveTheme.value) })

// ?theme=paper|ink 标签页预览（沿用 ?lang/?fun 三件套）
const q = new URLSearchParams(location.search).get('theme')
if (q === 'paper' || q === 'ink') { preview.value = q; sessionStorage.setItem(SS_KEY, q) }

export function setTheme(c: ThemeChoice) {
  themeChoice.value = c
  localStorage.setItem(LS_KEY, c)
  sessionStorage.removeItem(SS_KEY)
}
```

### 4.3 作用域策略

- **新组件一律 `<style scoped>`**（含 `:deep()` 用法约定）；现状仅 2/78 用 scoped 是历史包袱，不追溯强改；

### 4.4 内联样式三分法（451 处处置）

|---|---|---|---|

### 4.5 断点统一（双轨收敛）

现状 24 处 `@media`：720×6 / 760×2 / 640 / 480 / 900 / 1024×3 / 1280 + reduced-motion×12。

**收敛制：480 / 720 / 1024 / 1280 四主断点**（desktop-first 保留 max-width 写法，不做 mobile-first 翻转——6304 行存量的翻转成本远超收益，是刻意的保守）：

| 现值 | 归并 | 理由 |
|---|---|---|
| 720（×6） | **720** | 主移动断点 |
| 760（×2） | 720 | 双轨病灶（L1112「响应式」区 vs L2736「移动端适配」区各持一值），40px 差异无设计意图 |
| 640（×2） | 720 | 仅 L4595 一处 media + 容器宽，并档无感知 |
| 900 | 1024 | 平板档归一；两处规则需目验（L5515 抽屉/导航密度） |
| 480 | **480** | 小屏特调保留 |
| 1280 | **1280** | 容器上限联动 |

守护：stylelint `media-feature-name-value-no-unknown` + 自定义 `--alpha-value` 白名单（只许 480/720/1024/1280 出现在 max-width/min-width）——**只许收敛，不许新增断点值**。

与 03 §10 的接口：**720 同时是 TabBar 启用线**（<720 启用底部导航，03 §10.2）——主移动断点与 IA 切换线共用一个值，禁止再劈出第三条线；R1/R2 的 50% 缩放律同以 720 为翻倍点。

### 4.6 stylepkg 裁决（Tailwind 与 variables.css）

- **不引入 Tailwind 运行时**。理由：①6304 行手写 CSS 是已验证资产，引入 Tailwind 意味着重写全部类名语义；②78 个组件 + 451 内联的改写触面与 §6 否决重写的同一组数据矛盾；③项目零 lint 零测试，引入新 DSL 的学习/构建双成本无护栏。
- **SKILL.md 的价值重定位**：它是 Tailwind 语系的生成模板，无机器执行面。v3 把它用作「翻译词典」——附一份 `Tailwind class ↔ 本站 token/class` 对照表（border-4→var(--border-w)、shadow-[8px_8px_0_#000]→var(--shadow-lg)、rounded-none→缺省…），供 AI 辅助生成时把词汇翻译成本站语系。**规范文档与实现不同语系**的病根（01 §3.3）不靠接线 Tailwind 治，靠词典 + lint 白名单治。
- **variables.css（shadcn HSL 体系）不采纳**：HSL 三元组格式（`0 0% 0%`）依赖 `hsl(var(--x))` 包裹语法，与本站直读 hex 语义 token 冲突；且项目无 shadcn 依赖。其 `.dark` 节的结构（哪些角色需要覆盖）可作墨黑主题完备性的参照清单。
- `tailwind-preset.js` 维持未接线状态（01 已证零引用），在 v3 文档层标记「参照物，非依赖」。

### 4.7 禁止项机器化（stylelint 守护清单）

两条立规来源合并：①提炼文档「匹配即拒绝」禁止项（合并 playful 与 plain 两份清单，补 border-gray-\*）；②03 §11.1 的「组件层禁止字面色值」（本文 §3.1 铁律 2 的机器化）。

```js
// stylelint.config.js 核心规则（禁止项 → 机器规则）
module.exports = {
  rules: {
    'property-disallowed-list': ['border-radius'],                    // 直角铁律（现全文件 0 声明，守护不再犯）
    'declaration-property-value-disallowed-list': {
      'box-shadow': ['inset*'],                                       // 硬影以外的 inset 模糊影
    },
    'function-disallowed-list': [],                                   // gradient 白名单：仅 tokens/ 与滚动条纹理例外（ignoreFiles 配置）
    'declaration-property-value-allowed-list': {
      'color|background-color|border*-color': ['/^var\\(--/', '/^transparent$/'],  // L3 只准引用 token（§3.1 铁律）
    },
    'declaration-no-important': true,                                 // 现仅 4 处，收编后清零
    'max-nesting-depth': 3,
    'media-feature-name-value-allowed-list': ...                      // §4.5 断点白名单（自定义 plugin）
  },
}
```

配套：`npm run lint:css` 进 CI；**统一禁止模式表**（提炼文档对账表第 5 行裁决：合并 playful 与 plain 两份清单为一份，补 `border-gray-*/border-slate-*` 禁令，落进 tokens 文档随代码走）；SKILL.md 禁止项的 regex 版（`^rounded-(sm|md|lg|xl|2xl|3xl|full)$` 等）翻译成上表规则——**文档与机器校验从此一份口径**。

**R8「静止态 rotate 非零」的静态检查评估（v3.2）**：纯 stylelint **无法可靠区分「静止 vs 瞬时」**——`declaration-property-value-disallowed-list: { transform: ['*rotate*'] }` 会连 `:active` 微倾与 `@keyframes` stamp 轨迹一起误杀。可行的是自定义插件按选择器上下文放行（`:active/:focus/@keyframes` + 装饰类名白名单 `*stamp*/*badge*/ann-pin/forum-peek`），但「装饰」是语义判断、类名白名单随组件新增漂移，维护成本 > 收益。**落地口径**：stylelint 只做粗防线（transform 含 rotate 且选择器非伪类/关键帧/白名单 → warning，拦新犯）；**CDP computed-style 反解 rotate 为权威门**（§3.7 静止倾斜断言行，能拦住内联样式与组件态，stylelint 做不到）。

### 5.7 工程化最小集（按投入产出排序）

1. **stylelint**（§4.7）——禁止项机器化，直接堵住「第 81 个分区」的再犯路径；半天。
2. **vitest 冒烟**（不追覆盖率）：①token 完备性测试——扫描所有 CSS 引用的 `var(--x)`，断言已定义（现值 4 个断 token，这类伤再无死角）；②全主题对比度表（§3.7）；③路由表快照（24 条路由可解析）。一天。
3. **CI 三步门**（GitHub Actions）：`npm run typecheck && npm run lint:css && npm run build` + 冒烟。半天。测试扩面（组件测试/E2E）明确列为 v3 非目标——工程化从 0 到 1 的第一步是「回归不靠人肉」，不是「覆盖率」。

## 6. 迁移策略论证（渐进 vs 重写 vs strangler）

### 6.1 三方案定义

- **A 全量重写**：新建 design-system 包 + 组件库，78 组件/25 视图在新体系下重写，一次切换。
- **B 渐进原位演进**：既有代码原地分层——token 先行 → style.css 机械拆迁 → 主题/动效令牌 → 逐页收编内联样式；路由级灰度无需切换机制（全程单树）。
- **C Strangler（绞杀者）**：新旧两棵 UI 树并存，按路由逐页迁移，旧页由旧壳渲染直到全部替换。

### 6.2 评估矩阵（8 维 × 3 案）

| 维度 | A 重写 | B 渐进 | C strangler | 数据锚点 |
|---|---|---|---|---|
| 触面/风险 | 78 组件+25 视图全改 | 逐步小批 | 每页切换一次 | 01 §1.2 |
| 工期（1 人） | 6-10 周（无并行） | P0-P2 ≈ 1.5 周见效 | 与 A 相当+协调成本 | 本 §6.4 |
| 过渡期体积 | 一次性切换，无双载 | 无双载（单 CSS 树分层） | **双 CSS 树共存互踩**（见 6.3） | 架构事实 |
| 主题架构契合 | 高（新架构天然多层） | 高（§3 即按存量语义层设计） | 低（双树=双 token 体系，主题×2） | §3 |
| 可回滚性 | 差（重写期旧版冻结，回头即弃工） | **每 commit 可回滚** | 中（切页可退，但双树维护累） | — |
| 隐性契约 | **大量流失**（KeepAlive key 三规则/scrollBehavior 踩坑/代理 Host 分叉注释） | 原地保留 | 部分保留 | 01 §6/App.vue L19-27 注释 |
| 资产利用 | types(62 引用)/14 原语重写浪费 | 全保留 | 半保留 | 01 §7 |
| 团队适配 | 1 人不可承受 | **1 人节奏友好**（每期独立交付） | 双树期间等于两人份维护 | 01 §8 三无现状 |

### 6.3 逐案论证

**C（strangler）否决——三条硬伤**：

1. **CSS 全局性互踩**：本站样式是全局单树（style.css 全局 + 2/78 scoped）。strangler 双树并存意味着新旧两套全局 CSS 同时生效——同名的 `.btn/.card/.container` 会互相覆盖，级联顺序成了定时炸弹。规避手段只有 micro-frontend 级隔离（qiankun/module federation/iframe）——为一次样式迁移引入微前端基础设施，对一个无 CI 无测试的 1 人项目是**用火箭拖板车**。
2. **双载成本**：过渡期用户按路由加载两套 token 体系（108KB 旧 + 新分层），包体积与内存双倍；主题切换（§3）必须在两套体系间同步，换装逻辑×2。
3. **价值错配**：strangler 的适用前提是「旧系统不能停机、不能大改」——本站是内容站（非交易系统），允许逐 commit 部署、允许样式渐变；没有「必须双树」的刚性约束。

**A（重写）否决——四条硬伤**：

1. **无回归安全网**：0 测试/0 lint/0 CI（01 §4.4）。重写 78 组件等于盲飞——每次「看起来一样」都无法证明「行为一样」；KeepAlive key 规则、scrollBehavior 的「fullPath 当 key 导致滚动弹顶」这类用事故换来的知识全在注释里（App.vue L19-27），重写必再踩一遍。
2. **触面数据**：451 内联样式 + 80 分区地层 + 10 类职责的 UploadView——重写是把这些债**先放大再偿还**（重写期功能冻结，v3 的功能需求池「有引擎没方向盘」五件事（02 §6.2-1）全部排队等待）。
3. **资产浪费**：`api/types.ts` 62 引用、14 个真共享原语、adminQueues 单一口径、funMode 三铁律注释——重写路径上最值钱的部分恰恰是这些「不是样式的东西」，它们与视觉重构正交，绑在一起重写纯属陪葬。
4. **用户决策矛盾**：用户已拍板「保留并完善」——重写天然与「完善」相悖（重写=换血）。

**B（渐进）胜出——与约束全兼容**：

- token 先行（P0/P1）不触组件模板，风险面≈0；机械拆迁（保序搬移）有视觉回归兜底；
- 主题架构按「存量语义层即 L2」设计（§3.1），**改造成本被刻意压到声明搬移级别**；
- 每期独立可交付可回滚，与 17 天 8.3 倍的样式增长曲线对冲（拆完即止住增量堆积）；
- 唯一弱点是「终态不完美」（pages/ 过渡态、scoped 比例渐进上升）——但这是 1 人团队的诚实路线，且终态差距有明确收敛机制（§4.3）。

### 6.4 结论与分期路线图

**结论：B 渐进原位演进。** 口诀：**先止血、再立骨、后换装、终收编**。
