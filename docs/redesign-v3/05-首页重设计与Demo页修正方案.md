### 1.5 「太丑」的正面诊断（用户痛点回应）

现状两处丑的**结构性根因**（对照 stylekit 的排版纪律）：

1. **`.section` 入口胶囊行**：5 个独立描边卡横排，每卡内嵌「章+标题+计数」三层小件——**边框过载+三层内嵌**导致每个胶囊都是「盒中盒」，视觉噪音大而无主次。stylekit 的同位组件（按场景浏览条）用**一根 border-r 分隔线**统摄全部项：边框数量从 5×4 边降到 5 根竖线，**组件少而精**。
2. **hub-side 侧栏**：4 张 side-card 纵叠，每张=完整边框盒+标题行+行列表——**同一种盒子重复 4 次**，页面右缘变成「边框的柱子」。stylekit 的纪律是**用分隔线与留白分层级，不用盒子包一切**——层级靠 11px 大写字距小标题+行列表的疏密，而非边框。

### 2.2 方案 B「枢纽即 hero」（列出不推荐）

侧栏内容全部前置融入 hero：公告墙=hero 右列视觉主件、热帖/榜单速览并入站点导航条带上方成「社区条带」。
- 取舍：信息密度前置（回访者首屏即见社区活性）——**但** hero 右列被公告墙占据后，「作品即门面」的气场丢失（公告是运营件不是审美件），且 hero 高度暴涨（首屏滚动比恶化）。
- 与「傻子也能用溜」冲突：首屏承担 4 类信息（作品/公告/热帖/榜单）→ 希克定律超载。**不推荐**，仅在「公告就是本站生命线」的运营期才值得考虑。

### 2.3 方案 C「保守轻改」（列出备选）

结构不动（胶囊行+侧栏保留），只做排版纪律修复：胶囊去独立边框改共享 border-r 条带形；side-card 改「顶部 2px 实线+无侧边框」的轻盒。
- 取舍：改动最小（纯 CSS 编排级）、无回归风险——**但**「丑」的根因（盒子包一切、无层级）只解决一半，hero 气场与数字条未升级。
- 适用场景：若本轮排期紧、只想止血观感。

### 2.4 推荐方案与理由

**推荐 A**。理由（对照标准+公理）：
1. **傻子也能用溜**：条带把 5 个入口压成一行编辑索引（米勒：组块化）；数字条让「站点规模/活性」一眼可见（透明性即信任 03 §3.2）；导航静默化后视觉焦点唯一收敛到 CTA（希克）。
2. **艺术家挑不出刺**：边框数量从胶囊行 20 边+侧栏 4 盒 → 区块分隔线 3 根+条带竖线 5 根（组件少而精）；留白节奏从「盒子间距」改为「border-b 分区+pt 阶梯」（stylekit 纪律）；编号/计数/反色全是**已有词汇的编排**，无新发明。
3. **03 公理在场**：渐进披露（灰测折叠/热帖 3 行/榜单 2 组节选+全部→）；显著度四通道（CTA=实底唯一强件）；守恒（入口复杂度转给条带编排而非用户记忆）。

### 2.5 明确「不做什么」

- 不动 6 项导航的信息架构/顺序/URL；不动 admin 用户菜单与徽章机制（t24 定稿）。
- 不动 tokens 四层/双主题/转场词汇（b-stamp-lite/0ms 硬切）/KeepAlive/打点/心跳。
- 不动 DemoCard/MasonryGrid/AnnouncementBlock 组件本体（只改其容器的编排）。
- 不引入 blur/圆角/浮钮等 stylekit 皮肤件（§1.4 拒绝清单）。
- hero 轮播主件若排期紧可降级为「精选第 1 件大图静态件」（无 dots 轮播）——不阻塞主方案。

## 3. 任务 2：Demo 页两处修正方案（根因→修法→风险，已读代码+CDP 实况复验）

### 3.1 preview-shell 被 dv-story 覆盖

**实况复验**（CDP 1360，demo-c004ab51）：
- 静态（scroll=0）：preview-shell bottom=717，dv-story top=741——**间距 24px，无覆盖**。
- 滚动 200/400/600：**重叠 172→274px**；重叠区 `elementFromPoint` 命中 `P`/`DIV.card card-default dv-desc-card`——**dv-story 的内容绘制在预览之上**，用户实况（预览被描述区盖住）复现。

**根因**（三层叠加）：
1. **sticky 容纳块过大**：`.dv-stage { position: sticky; top: 78px }`（DemoView.vue ~L392；样式 scoped）——其容纳块是父级 `.dv-shell`（**跨 row1+row2 的整块**，demo-detail.css `.dv-shell` 双列栅格），于是预览在整个 dv-shell 高度内持续 sticky，滚入 row2 区域时**预览仍钉在视口 78px 处**，与 dv-story（grid-row: 2，demo-detail.css L50-54）产生几何重叠。
2. **DOM 序绘制规则**：dv-story 是 dv-shell 中 dv-stage 之后的兄弟节点，无 z-index 时**后者绘制在上**——重叠区里 dv-story 的文字/卡片盖住预览下缘。
3. **无层叠声明兜底**：dv-stage 未设 z-index（实测 z: auto）——既没有「预览在上」的约定，也没有「互不重叠」的布局约束。

**修法（推荐 A：把 sticky 容纳块收窄到 row1——根治）**：
- 结构：`.dv-shell` 内 row1 包一层 `.dv-row-preview`（`grid-column: 1; grid-row: 1`，作为 dv-stage 的新父级）——dv-stage 的 sticky 容纳块随之变为 row1 包装层，**滚动到 dv-story 时预览被自然推出视口（标准 sticky 释放语义），几何上不可能再与 row2 重叠**。
- 同时 `.dv-story { grid-row: 2 }` 显式放置保留（t22 定稿语义不动）；facts rail（380px 列）不受影响（dv-facts 仍在 dv-shell 第 2 列）。
- 顺带收敛：预览高度 `68vh`（responsive-v1.css L91）在窄主列下偏高，可同步给 `.dv-stage` 加 `max-height: calc(100vh - 96px)`，保证 row1 高度与预览高度一致，释放点可预期。

**修法（备选 B：z-index 提层——否决，说明理由）**：给 dv-stage 设 `z-index: 1` 让预览盖住 dv-story——几何重叠依旧，只是换「谁盖谁」，结果变成**预览盖住描述文字**（更糟）。层叠法不解决重叠本身，仅记录为否决项。

**风险与回归清单**：
- dv-stage 多一层包装后，t23 已裁决的语义需回归：**sticky 跟随（跟随到 row1 底即停=标准语义，与 t23「末段随容器滚走」口径一致）**、**0ms 硬切（facts 收起/展开的列宽变化不受影响——改动只在 row1 内部结构）**、快捷键 I/localStorage 记忆不动。
- 改动文件与区间：`frontend/src/views/DemoView.vue`（模板 ~L391-394 dv-stage 开标签外包一层；闭合 ~L536 dv-story 之前）、`frontend/src/styles/pages/demo-detail.css`（.dv-row-preview 新增 ~L45-56 区间；dv-stage 的 sticky 声明处同步）。**注意 demo-detail.css 是全局 styles/（冻结令）**——若冻结令仍生效，把 .dv-row-preview 写进 DemoView scoped（推荐），demo-detail.css 仅零改动。
- 风险：低。纯布局层级变更，无动画/无主题/无数据影响；预期回归点仅 sticky 语义一处。

### 3.2 quick-comments 不要被折叠（常开化）

**现状定位**：讨论节包在 `<details class="dv-disclose">` 内，`open` 默认 **false**（CDP 实测 discloses：时间线 open=false、讨论 open=false；summary 文本「讨论 0 点开看评论并发言讨论 →」）——quick-comments（输入框 quick-comment-input + 列表 quick-comment-list）整体在折叠里。模板区间：`frontend/src/views/DemoView.vue` ~L536 dv-story 内的 dv-disclose ③时间线/④讨论两节（v2 阅读序③④）。

**根因**：v2 阅读序定稿时讨论与时间线一并设为 `details` 渐进披露（渐进披露公理的机械应用）——但**讨论是交互件不是阅读件**：发表入口藏在折叠里=发言门槛+1（用户「不要被折叠」的实质诉求：**发言零门槛常在**）。

**取舍分析（是否破坏 v2 纵向阅读序）**：
- v2 废除的是「四 Tab 立阅读序」，立的是**纵向单列阅读序**——常开④讨论**不破坏**纵向序（仍是 ①预览→②它是什么→③时间线→④讨论 的纵向流），只是④默认展开、页面变长。
- 页面长度代价：讨论 0 条时展开=输入框+空态 ≈ +180px；有评论时列表自然生长——可接受（详情页本就是深度阅读页）。
- **与③时间线的关系**：若③④同时常开，「它是什么」与讨论之间隔着展开的时间线，讨论的到达感变弱。**建议差异化**：③时间线保持折叠（版本史是低频回看件，渐进披露公理正确适用）；④讨论常开（交互件常在，蔡格尼克：可见的输入框=未完成的发言邀请）。

**修法（推荐：差异化常开+轻量去折叠化）**：
1. ④讨论的 dv-disclose 设 `open`（`:open="true"` 初始展开）；**summary 保留但形态从「可展开关」改「节标题条」**——或者保守做法：summary 保留可点收起，只是默认 open（零风险，回滚容易）。推荐保守做法：`open` 属性由 `qcOpen = ref(true)` 驱动（默认常开、仍可手动收起、不持久化——每次进页重置为常开，因为这是默认偏好而非状态）。
2. 空态紧凑化：0 条评论时列表区给「还没有评论，抢个沙发 →」一行空态（不占高）；输入框恒在顶部。
3. 「讨论 N」计数徽章保留在 summary 右侧（常开后 summary=节标题，计数=仍然有用的概要信息）。

**风险**：
- 低。改动=`:open` 初始值+空态样式，不触碰评论提交逻辑/打点/防刷。
- 需回归：quick-comments 在移动端（500px）的展开高度；与底部动作条「讨论」键的衔接（b8380b7 的 scrollToRating 式滚动到位逻辑——目标从「滚到 summary」改「滚到输入框」，或不变均可）。
- 改动文件区间：`frontend/src/views/DemoView.vue` 模板 dv-disclose ④节（~L560-600 区间，以 grep `quick-comments` 实测为准）+ 空态 scoped 样式数行。

### 5.2 抽屉设计规格（用户 idea 转译：无边框/实线分割/落下回弹）

**应用对象（首批）**：作品库分面抽屉（`.facet-panel--overlay` + 钉住态）与移动 bottom-sheet（`.facet-panel--sheet`）；AnnouncementModal 同批归一；其余抽屉（PeekDrawer/筛选弹层等）随迭代归一。

**三律规格**：

1. **无边框**：抽屉容器去 `border: 4px solid var(--ink)` 与 `box-shadow: 8px 8px`——内容块以**纯色填充**直接着地（paper 底=纸面，ink 主题=paper-deep 系暗底），容器唯一视觉边界=**外部投影一刀**（`box-shadow: var(--shadow-black)` 单一硬影，或 0 影+2px 顶线，实施时二选一并全站统一）。
2. **实线分割**：组与组之间用 **2px 实线 divider**（`border-bottom: 2px solid var(--ink)` 或 --border-w token）替代「每组件一个边框盒」——分组节奏靠线不靠盒；divider 之上组头（11px 大写字距小标题）。
3. **摔下来有回弹（b-stamp-drop）**：

```css
/* 抽屉/弹层编排入场：落下→一次 overshoot→回弹→落定（stamp 家族·位移维度） */
@keyframes b-stamp-drop {
  0%   { transform: translateY(-14px); opacity: 0; }  /* 从上方 14px 落下 */
  58%  { transform: translateY(3px); opacity: 1; }     /* 越过落点（overshoot） */
  80%  { transform: translateY(-1px); }                /* 一次回弹 */
  100% { transform: translateY(0); }                   /* 落定 */
}
/* 用法：animation: b-stamp-drop var(--b-dur-stage) var(--b-ease-stamp) both; 同屏一实例 */
```

   - 时长/曲线**复用既有令牌**：`--b-dur-stage: 350ms` + `--b-ease-stamp: cubic-bezier(0.16, 1, 0.3, 1)`（easeOutExpo，04 §2 既有）——**零新增令牌**（用户口述的「350ms easeOutExpo 系变体」即此组合）。
   - **仲裁注记（与「无弹簧」红线的关系）**：03/04 红线「无弹簧」约束的是**交互过渡层**（--b-dur 150ms：hover/active 等用户触发态切换——弹性=失控感，禁止）；而 stamp 家族是**编排登场层**（--b-dur-stage 350ms），其隐喻本来就是「落下/盖章」——既有 b-stamp-in 的 60% 帧已内置一次过冲（scale 1.06→0.985→1），**「落下 overshoot→回弹一次→落定」与 stamp 语法同构**，b-stamp-drop 只是把该语法从缩放维度移植到位移维度（translateY）。**单次过冲、无持续振荡**（非 elastic spring），与红线不冲突；关闭侧维持 **0ms 硬切对称**（开有回弹、关即消失——词汇表抽屉行更新为「抽屉/弹层：b-stamp-drop 350ms 落下回弹一次 + 关闭 0ms 对称」）。
   - 红线遵守：同屏一实例（march 同款单实例纪律）；reduced-motion 下 animation:none（既有 0.01ms 闸+显式退场组双保险）；只动 transform+opacity（编排类白名单内）。

**规格落位与验收（抽屉节）**：

- [ ] 分面抽屉（overlay/sheet/钉住三态）容器无边框、组间 2px 实线 divider、入场 b-stamp-drop 350ms。
- [ ] bottom-sheet 落下回弹同规格（从底部上收的镜像语义：translateY 正向落下=自底部 `translateY(24px)` 落上——实施侧按「贴边方向落下」实现，规格同帧谱）。
- [ ] AnnouncementModal 开启=b-stamp-drop（弹层是横幅的伴生件，同批归一）；关闭 0ms。
- [ ] reduced-motion：三处动画全退场（直接出现）。
- [ ] 同屏仅一实例（开抽屉时关闭其他编排队列）。
