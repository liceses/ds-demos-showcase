# UI/UX 规范（唯一入口）

> 本目录是本站 **UI/UX 的唯一规范来源**。散落在别处的 UI/UX 文档要么被收编为 `log/`（轮次记录），
> 要么降级为"考古/提案"并在此登记链接。CSS 注释写的是**为什么**，本目录写的是**规范是什么**。

## 怎么用

| 你想做的事 | 读哪一章 |
|---|---|
| 改视觉/动效，先确认上位依据 | `01-宪章.md`（风格参考站四法则，含抓取日期与原文） |
| 加一个组件、或给组件加状态 | `04-组件.md`（七态矩阵）+ `02-原则.md`（灵魂清单与不做清单） |
| 写 hover/active | `06-微交互.md`（只许用 `.b-lift`，不许裸写物理） |
| 挑颜色/字号/间距/影/断点 | `03-令牌表.generated.md`（**生成物**，勿手改） |
| 响应式与首屏预算 | `05-布局与响应式.md` |
| 焦点/对比度/触达 | `07-无障碍.md` |
| 想破例 | `08-例外登记.md`（写理由 + 到期条件，否则门禁不认） |
| 想知道"这条规范谁在管" | `09-规范↔门禁对照.md`（每条条款 → 钉它的门禁） |

## 治理规则（三条铁律）

1. **规范条款必须带门禁**。新增/修改条款时，同一次提交里必须给出"谁来钉它"：
   vitest 护栏（`frontend/tests/designSystem.test.ts`）、stylelint、生成物 hash、或 CI 脚本。
   钉不住的条款只能进 `08-例外登记.md`，并写明到期条件。**没有门禁的规范会腐烂** —— 本站已经烂过一次：
   微动效散成 29 处手写抬升、20 个文件、6 种影值，还出过 5 组跨文件同名覆盖。
2. **能生成的不要手写**。令牌表由 `tooling/uiux-tokens.mjs` 从 `tokens/*.css` 生成并带 hash；
   迁移基线由 `tooling/uiux-physics-baseline.mjs` 从样式实读生成。手写过的数字本轮漂移过两次。
3. **例外必须可见**。任何"我们知道它不合规/与参考站不同"的地方都进 `08-例外登记.md`，写清
   理由、范围、**到期条件**（什么时候复审、谁能销账）。
