## 真实渲染实测抓到的两件事（门禁看不见的）

1. **`.dv-next-card` 静止影失效**：同文件两块定义、迁移块漏了 `box-shadow: var(--lift-sh)`，
   库默认影同特异度输给导入顺序 ⇒ 4px 黑影赢、`--lift-sh` 成死变量。修复后实测 rest `none` → hover `12px 红` + 换黄底。
   新增**门禁⑪**钉住这一整类，并**证明有牙**（撤掉修复即红，诊断精确指出被谁盖住）。
2. **`.ann-card*` 疑似死样式**：只在 CSS、模板无引用 ⇒ 迁移可能是空改（已登记）。

## 方法沉淀（踩过的坑）

- **dev server 必须与测量同作业**：`Start-Process` 起的服务会随工具调用结束而死（这解释了三次"整轮全 0"）。
- **有数据的页面才测得出**：预览库无论坛数据 ⇒ 论坛类组件改走"改动后前端 + 生产真实数据"（5190，只读）；
  或先给预览库喂数据。**绝不对生产登录/写操作**。
- **正则删 CSS 会踩多行选择器**：`@reduce` 批量删除时留下悬空选择器（`.uw-step.active,` 后直接 `}`）⇒ build 红。
  CSS 的多行选择器列表必须整块编辑。
- **门禁必须证明有牙**：新门禁要能"撤掉对应修复即变红"，否则只是摆设（门禁⑪就是这么验的）。
