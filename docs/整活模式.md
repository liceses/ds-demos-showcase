# 整活模式（astra 灰测作品收集）

> 2026-08-30 上线。纯显示层整活：开启后全站把 `model:ds-unknown` 显示为 `astra-canary`，
> 站点标题（首页 hero、顶栏品牌、浏览器标题、页脚）切换为「astra 灰测作品收集」。
> **不改任何数据、URL、路由参数、请求载荷与上传行为**——关掉即完全复原。

## 一、开关与传播链路

```
管理后台 → 设置 → 「整活模式（astra 灰测作品收集）」勾选 → 保存设置
  └─ PUT /admin/settings {fun_mode: true}        ← 后端 Setting 表新 key（唯一后端改动）
       └─ 前端本端立即生效（applyServerFunMode）
       └─ GET /meta/site-info?refresh=1          ← admin 强刷后端 60s 内存缓存
            └─ site-info.display.fun_mode = true  ← 全站访客的读取点
                 └─ 访客：App.vue 启动时拉 site-info 校正本地 flag
```

- **传播延迟**：后端内存缓存 60s + CDN 缓存 60s → 全站访客最迟 ~2 分钟内切换；admin 本端即时。
- **防闪烁**：前端把上次已知状态镜像在 `localStorage.dsh_fun_mode`，上屏先用缓存值，fetch 回来校正。
- **预览模式**：URL 带 `?fun=1` / `?fun=0` 只影响当前标签页（sessionStorage），供 admin 先看效果再全站开。

## 二、三条铁律（防 bug 边界，改动前必读）

1. **只改渲染文案**。标签值替换用**全等匹配**（`value === 'ds-unknown'`），绝不做子串/自由文本替换；
   数据、URL（`/tag/model/ds-unknown`）、请求载荷、点击复制的内容永远是原始值——
   复制成 `astra-canary` 再贴进筛选框会变成死链，因此复制行为保持原值。
2. **自由文本不碰**：prompt 正文、description、公告、论坛 Markdown 内容里出现的 `ds-unknown` 一律不动。
3. **管理后台豁免**：`/admin` 路由下整活自动失效（恒显真实值），避免管理员把 `astra-canary` 当真值再建一遍。

## 三、前端实现（单点翻译器）

核心：`frontend/src/utils/funMode.ts`

- `funMode`（ref，全站开关）+ `adminExempt`（路由豁免，App.vue watch 维护）+ `preview`（?fun 覆盖）
  → `funEffective` computed；
- `tagLabel(v)`：标签值显示翻译（全等）；`tagStrLabel(s)`："key:value" 字符串版（已选筛选 chips 用）；
- `titleBase` computed：站点标题文案；
- `applyServerFunMode(on)`：写入开关 + localStorage 镜像。

响应式关键点：所有渲染点引用同一组 `ref/computed`，**开关切换后所有页面（含 keepAlive 缓存的
首页/作品库）自动重渲染**，无需刷新——这是避免"半新半旧"的关键。

### 渲染点接入清单（显示文案包 tagLabel，:key/路由/复制保持原值）

| 文件 | 位置 |
|---|---|
| `App.vue` | 顶栏品牌（两行节奏 `astra 灰测<br>作品收集`）、页脚首行、路由豁免 watch、启动同步 |
| `router/index.ts` | `document.title` 后缀走 `titleBase` |
| `HomeView.vue` | 首页 hero 大标题、灰测区标题 |
| `DemoCard.vue` | 卡片标签 chips（`label()` 内） |
| `GroupedTagValues.vue` / `TagGroupBox.vue` | 分组值 chips（点击复制/跳转仍原值） |
| `DemosView.vue` | 已选筛选 chips（tagStrLabel）、热门快捷 chips、分组筛选条 chips |
| `DemoView.vue` | 详情页标签区 |
| `TagListView.vue` | 标签分布条 |
| `TagDetailView.vue` | 面包屑父标签、h1、子标签 chips（forum 链接 query 保持原值） |

## 四、后端改动（仅此一处）

| 文件 | 改动 |
|---|---|
| `services/settings_service.py` | `KEY_FUN_MODE` + `get_fun_mode` / `set_fun_mode`（照抄 auto_approve 模式） |
| `schemas.py SettingsOut` | `fun_mode: bool \| None = None`——**PUT 时 None = 保持不变**，旧调用方漏带字段不会静默关闭整活 |
| `routers/admin.py` | GET 返回实际值；PUT 仅显式传入时更新 |
| `services/site_info_service.py` | `_build()` 增加 `"display": {"fun_mode": ...}`（对外广播点） |

无表结构变更（复用 settings 键值表，首次 PUT 才落行）、无迁移。

## 五、API 变更摘要

- `GET/PUT /api/v1/admin/settings`：增 `fun_mode` 字段（GET bool；PUT 可省略 = 不动）。
- `GET /api/v1/meta/site-info`：增 `display: {fun_mode: boolean}`；admin 仍可 `?refresh=1` 强刷缓存。
- 兼容性：旧前端忽略新字段不受影响；新前端对旧后端 `display` 为 undefined 时按关处理。

## 六、排障

| 现象 | 检查 |
|---|---|
| 开了但访客没变化 | site-info 双层缓存 ~2 分钟；确认 `GET /meta/site-info` 返回 `display.fun_mode: true` |
| admin 本端没即时变 | 保存后会自动 refresh=1 强刷；检查浏览器控制台 /admin/settings PUT 响应 |
| 某处仍显示 ds-unknown | 预期内——漏包 tagLabel 的角落显示原值，不是 bug；补一层即可 |
| 想立即看效果不想等 | `?fun=1` 当前标签页预览 |
| 复制出来是 astra-canary？ | 不会——复制恒为原值 `ds-unknown`（铁律 1） |
