# 论坛安全调查报告（deepdemos 小站适配）

> 状态：调查报告 / 方案建议稿
> 目标：为 deepdemos 论坛模块提供适合小站的防刷帖、防非法链接、防滥用方案。
> 定位：不追求一步到位，先做“低成本高收益”的分层防护。

---

## 一、背景

deepdemos 是一个以 AI 网页 Demo 展示为主的小站，技术栈：

- 前端：Vue 3 + TypeScript + Vite
- 后端：FastAPI + SQLAlchemy + SQLite
- 认证：本地账号（用户名 + 密码）+ JWT HttpOnly Cookie
- 现状：已有匿名上传、评分、会话日志等基础限流；无论坛模块

论坛模块规划中，需要防止：

1. 大量刷帖（机器人 / 恶意灌水）
2. 未知 / 非法网站链接（赌博、色情、诈骗、钓鱼等）
3. 恶意内容（XSS、垃圾广告、攻击性内容）

## 三、安全威胁分析

| 威胁 | 说明 | 常见原因 |
|---|---|---|
| 批量刷帖 | 同一账号/IP 短时间内大量发帖 | 无身份门槛、无限流 |
| 注册轰炸 | 批量注册小号 | 无验证、无注册限流 |
| 垃圾广告链接 | 帖子内塞外链 | 无链接校验、无黑名单 |
| 恶意/钓鱼链接 | 跳转到仿冒站点 | 无外链提示/跳转页 |
| XSS | 帖子内容带脚本 | 未消毒 HTML |
| SSRF/内网探测 | 链接指向内网地址 | 未校验 URL 目标 |
| 滥用/攻击性内容 | 辱骂、引战 | 无审核、无举报、无封禁 |

## 4. 适合小站的 5 层防护

### 4.1 身份门槛

- 发帖 / 回复必须登录，匿名只能浏览。
- 不强制 GitHub 登录，但可把 GitHub 绑定作为“信任等级”加分项：
  - 本地账号也能发；
  - GitHub 绑定账号标记为高信任，可少审核；
  - 新账号 / 低信任账号发帖先进审核队列。
- 参考 Discourse 的信任等级机制：新用户先受限，正常发言后逐步放权。

### 4.2 发帖 / 回复限流

- 按“用户 + IP”双维度限流：
  - 新用户：5 帖/小时、20 回复/小时；
  - 老用户：20 帖/小时、60 回复/小时；
  - 同一 IP 匿名操作全局限流。
- 可复用现有 `defaultdict + 时间窗口` 的限流模式，成本低。
- 参考 Flarum AntiFlood 扩展。

### 4.3 新用户审核 + 举报

- 新注册用户前 1~3 条主题 / 回复进入“待审”，管理员放行后才公开。
- 已有用户发帖不审核，但提供举报按钮。
- 管理员可隐藏 / 删除帖子、封禁用户。
- 这是 Discourse、Reddit、Flarum 都采用的“低信任先审、高信任放行”模式。

### 4.4 链接安全

小站不需要复杂 AI 检测，先做硬校验：

- 帖子内 Markdown 链接只允许 `http://` / `https://`；
- 后端解析每个链接域名：
  - 拒绝内网 / 回环 / 链路本地 / 保留地址（防 SSRF）；
  - 拒绝非常规端口（如 `:22`、`:3389`）；
  - 拒绝 URL 中带 `@` 混淆、IP 直连；
- 维护域名黑名单（赌博 / 色情 / 诈骗等），命中直接拒绝或转审核；
- 可选：外链安全跳转页 `/redirect?url=...`，点击时提示“此链接将离开本站”。

### 4.5 Markdown / XSS 安全

- 前端渲染用 DOMPurify 消毒，禁止原始 HTML；
- 后端只存 Markdown 文本，不做 HTML 渲染；
- 帖子内容长度限制（如正文 50000 字符）；
- MVP 阶段不开放附件，减少文件类攻击面。

## 5. 最小落地清单

```text
优先级 P0（必须做）：
1. 发帖/回复必须登录
2. 发帖/回复限流（用户 + IP）
3. Markdown 渲染消毒
4. 链接只允许 http/https + 域名校验 + 内网地址拒绝

优先级 P1（强烈建议）：
5. 新用户前 3 帖进审核队列
6. 管理员可删除/隐藏帖子、封禁用户
7. 举报按钮

优先级 P2（后续增强）：
8. GitHub 登录作为可选“信任身份”
9. 外链安全跳转页
10. 域名黑名单自动更新
```

## 6. 关于 GitHub 登录的结论

网络实践表明：**光靠 GitHub 登录不能解决刷帖和非法链接**，因为 GitHub 小号成本低。

它更适合作为“信任等级”的加分项，而不是唯一门槛。

对小站来说，先做：

```text
登录 + 限流 + 链接校验 + 审核/举报
```

性价比最高，等社区活跃后再考虑 GitHub 绑定。

---

## 7. 与当前项目的结合建议

- 复用现有 FastAPI 限流模式（`defaultdict + 时间窗口`）。
- 复用现有前端 `MarkdownRenderer`（DOMPurify 消毒）。
- 论坛管理后台可与现有 Admin 后台合并，复用管理员权限。
- 链接校验可复用现有 `_assert_public_url` 的 SSRF 防护思路。
- GitHub 登录作为独立 Auth Provider 设计，不阻塞论坛 MVP。
