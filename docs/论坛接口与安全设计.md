# 论坛接口与安全设计

> 配套：`../API_CONTRACT.md`（全量契约）、`../backend-design.md`（实现要点）、`论坛安全调查报告.md`（安全审计）。
> 本文聚焦论坛后端：数据模型 / API / 安全机制 / 前端对接点 / 迁移。

## 一、数据模型

### `forum_topics`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | |
| title | str(200) | 主题标题 |
| content | text | Markdown 原文（前端渲染时消毒） |
| author_id | FK users SET NULL | 发帖人 |
| demo_slug | str(128) nullable | 关联 demo（富卡片） |
| category | str(32) | 分类（general/demo/...） |
| tags | str(200) | 逗号分隔 |
| pinned / sticky | bool | 置顶 / 加精 |
| status | str(16) | `normal` / `hidden` / `reviewing` |
| reply_count / view_count | int | |
| created_at / updated_at | datetime | |

### `forum_replies`
- id, topic_id（级联删）, author_id, content, `status`（normal/hidden/reviewing）, created_at

### `forum_reports`
- id, target_type(topic\|reply), target_id, reporter_id, reason, status(open\|resolved\|dismissed), created_at

### `users` 扩展
- `trust_level`（0=新用户需审核，>=1 正常）
- `need_review`（bool）
- `github_bound`（bool，备用）

## 二、API

### 公开（匿名只读）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/forum/topics` | 分页/搜索(q)/分类/标签(tag)/demo/排序(newest\|popular)，仅 `normal` |
| GET | `/forum/topics/{id}` | 详情（view_count+1，含富卡片字段） |
| GET | `/forum/topics/{id}/replies` | 回复列表（仅 normal，时间升序） |

### 登录（发帖/回复/举报）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/forum/topics` | 发帖（限流 10/小时，用户+IP）；新用户进 `reviewing` |
| POST | `/forum/topics/{id}/replies` | 回复（限流 30/小时）；新用户进 `reviewing` |
| POST | `/forum/reports` | 举报主题/回复（限流 20/小时） |

请求体：
```json
// 发帖
{ "title": "标题", "content": "Markdown", "demo_slug": "slug?", "category": "demo", "tags": "canvas,game" }
// 回复
{ "content": "..." }
// 举报
{ "target_type": "topic|reply", "target_id": 1, "reason": "..." }
```

### 管理（admin）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/forum/admin/topics?status=reviewing` | 含 hidden/reviewing 全量 |
| PUT | `/forum/admin/topics/{id}` | 改 pinned/sticky/category/status |
| POST | `/forum/admin/topics/{id}/review` | `{action:approve\|reject}` 审核主题 |
| POST | `/forum/admin/replies/{id}/review` | `{action:approve\|reject}` 审核回复 |
| DELETE | `/forum/admin/topics/{id}` | 删主题（回复级联） |
| DELETE | `/forum/admin/replies/{id}` | 删回复（同步 reply_count） |
| POST | `/forum/admin/users/{uid}/ban` | 封禁用户 |
| GET | `/forum/admin/reports?status=open` | 举报列表 |
| POST | `/forum/admin/reports/{id}/handle` | `{action:resolve\|dismiss}` |
| GET | `/forum/admin/replies?topic_id=&status=` | 回复管理列表（含 hidden/reviewing） |

### 首帖初始化
- 启动时幂等创建置顶「论坛发帖须知 & 安全说明」（`category=notice`，`pinned/sticky=true`）
- 内容读取 `docs/论坛首帖-用户须知与安全说明.md`（缺失用内置兜底）
- 作者：admin 账号（存在则用，否则 null）

### 公告 ↔ 论坛互链
- `Announcement.topic_id`（可空，FK forum_topics SET NULL）
- 创建/更新公告可传 `topic_id`（校验主题存在且 normal）
- 公告响应带 `topic_id` / `topic_title`，前端显示「去讨论 →」

### 限流提示
- 429 响应带 `Retry-After` 头 + detail 含剩余冷却秒数，前端可提示「X 秒后重试」

## 三、安全机制

1. **登录门槛**：发帖/回复/举报必须登录；匿名只能读。
2. **限流**：用户 + IP 双维度（发帖 10 / 回复 30 / 举报 20，每小时）。
3. **新用户审核**：`need_review` 或 `trust_level<1` → 内容进 `reviewing`；admin approve 后置 `normal` 并把作者 `trust_level=1`、`need_review=false`。
4. **链接校验**：内容里的 http(s) 链接会被解析 DNS，拒绝内网/回环/保留地址 + 域名黑名单（`localhost/127.0.0.1/::1/example.com/test`）。
5. **Markdown 只存原文**，前端用消毒后的 MarkdownRenderer 渲染（XSS 过滤）。
6. **封禁**：`status=banned` 的用户在认证层直接 403。
7. **举报闭环**：用户举报 → admin 处理（resolve/dismiss）。

## 四、前端对接点

- 列表/详情/回复直接消费公开接口。
- 发帖/回复表单：提交后若返回 `status=reviewing`，提示「内容已提交，等待管理员审核」。
- 富卡片：论坛主题关联 `demo_slug` 时，用 `GET /demos/{slug}/meta` 拉 `{slug,title,cover_url,author}`（**不增加浏览数**）渲染作品卡。
- 举报按钮：调 `POST /forum/reports`，成功后提示「已举报」。
- admin 页：审核队列用 `/forum/admin/topics?status=reviewing` + review 接口；举报用 `/forum/admin/reports`。

## 五、迁移脚本

```bash
# 把历史 comments 按 demo 归集为论坛主题 + 回复（幂等）
python scripts/migrate_comments_to_forum.py
# 容器内
docker compose exec backend python /site-repo/scripts/migrate_comments_to_forum.py
```
- 每个有评论的 demo **创建或复用**一个主题（标题「{demo.title} 的讨论」，category=demo）
- 保留 `author_id` / `content` / `created_at`
- 以 `forum_replies.source_comment_id` 幂等去重，重复执行不产生重复楼层
- 最后检查孤儿评论（comments 指向已不存在的 demo）
