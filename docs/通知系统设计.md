# 通知系统设计（记录稿）

> 目标：用户评论 Demo、Demo 审核、论坛回复等关键动作能通知到相关人；同时保持主站纯净，不往首页塞信息流。

## 一、核心原则

- 主站/论坛**共用一套通知**，入口是顶栏**小铃铛图标**（未读红点）
- 点击进独立页 `/notifications`，**首页零改动**
- 论坛顶栏复用同一个铃铛组件

## 二、通知类型

| 类型 | 触发 | 通知谁 |
|---|---|---|
| 作品评论 | 有人评论/回复你的 Demo | Demo 作者（注册用户） |
| 作品审核 | 新 Demo 待审核 | 所有管理员 |
| 审核结果 | 你的 Demo 通过/拒绝 | 作者 |
| 论坛回复 | 有人回复你的主题/回复 | 主题作者 + 被 @ 的人 |
| 举报处理 | 举报被处理/忽略 | 举报人 |
| 系统 | 公告/封禁等 | 相关用户 |

## 三、外部站点借鉴

- **GitHub**：通知收件箱 + 未读红点 + 按原因分组 + 全部已读
- **Reddit**：inbox 分「回复 / 提及 / 消息」，点开即上下文
- **Discord**：未读徽标 + 点击跳到对应内容
- **Hugging Face**：铃铛 + 通知列表，点通知跳转对应页面

## 四、前端设计

### 1. `NotificationBell` 组件
- 顶栏铃铛 + 未读红点
- 轮询 30s（或 SSE）未读数
- 主站/论坛共用

### 2. `/notifications` 页
- 分组 Tab：**作品 / 论坛 / 管理**
- 每条：图标 + 文案（如「alice 评论了你的 Demo《xxx》」）+ 时间 + 未读高亮
- 操作：单条已读 / 全部已读；点击跳转对应 Demo/主题

### 3. `stores/notifications.ts`
- 未读数 + 列表缓存，跨页面共享

## 五、后端配合

- `Notification` 表：`user_id / type / actor_id / demo_slug? / topic_id? / reply_id? / read / created_at`
- 在评论/回复/审核/举报动作里创建通知
- 接口：
  - `GET /notifications`（分页 + 未读筛选）
  - `POST /notifications/read`（单条已读）
  - `POST /notifications/read-all`
  - `GET /notifications/unread-count`

## 六、保持主站纯净

- 首页零改动：不加通知流、不加卡片
- 铃铛只是顶栏一个小图标（黑边小方块 + 红点）
- 通知内容全部收在独立页

## 七、实施优先级

1. 作品评论通知 + 审核通知 + 论坛回复通知（核心三类）
2. 管理通知（新举报/新建议）
3. 邮件/Web Push（后期可选）
