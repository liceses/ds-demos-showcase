## 1. 当前预览架构（终态）

```
浏览器
 ├── 主站  http://deepdemos.top            （nginx: SPA + /api → backend）
 └── 预览 iframe
        src = http://demo.deepdemos.top/preview/<slug>/v<版本号>/index.html   ← 与主站“不同源”
              │
              └─ nginx（demo.deepdemos.top 只放行 /preview、/media，其余 404）
                    └─ backend FastAPI /preview/<slug>/v<版本号>/{path}（旧无版本路径仍兼容）
                          ├─ .html → 由后端返回并注入 <base>：
                          │     版本化 URL 注入相对 <base href="/preview/<slug>/v<版本号>/">（当前线上形态，子资源同走版本化路径）；
                          │     旧无版本路径 + OSS 直连模式（OSS_SERVE_LOCAL=false）才注入 OSS 桶域名
                          ├─ 非 .html 且 OSS 开启且 OSS_SERVE_LOCAL=false → 302 → OSS（js/css/img 子资源，不受 Content-Disposition 影响）
                          │     （OSS_SERVE_LOCAL=true 时由后端直出 —— 2026-08-28 线上实测为该模式，见下方注记）
                          └─ OSS 未开 → 直接读本地 storage 返回
```

- 前端沙箱规则（`IframePreview.vue`）：`allow-scripts allow-modals allow-forms allow-popups allow-pointer-lock`，
  **仅当 iframe 与主站不同源时才追加 `allow-same-origin`**；不含 `allow-fullscreen`（浏览器判非法 flag，全屏走 `allowfullscreen` + `allow="fullscreen"`）。
- 后端 `preview_url`（`serializers.py`）取值优先级：
  1. `PREVIEW_BASE_URL`（如 `http://demo.deepdemos.top`）→ `${PREVIEW_BASE_URL}/preview/<slug>/v<版本号>/index.html`；
  2. 否则 `/preview/<slug>/v<版本号>/index.html`（本地/默认本地服务模式）。
  - 版本号 = `demo.updated_at` 时间戳（历史数据无 `updated_at` 时用 `created_at`）。
  - OSS 直连模式（`OSS_SERVE_LOCAL=false`）下，子资源经版本化路径 302 到 OSS 时追加 `?v=<版本号>`，CDN 按 query 区分缓存。

> **2026-08-28 线上实测快照**（deepdemos.top）：`OSS_SERVE_LOCAL=true`（默认本地服务模式）——预览子资源（js/css）、zip 下载、`/media` 封面均由源站 **200 直出**（无 302），配合 Cloudflare 边缘缓存承担带宽；OSS 实际仅双写备份 + 会话日志。本文中「302 直连 OSS」的描述对应 `false` 模式，当前线上未启用。主站与预览子域均为 **https**（Cloudflare 边缘终止，回源 http，nginx 仅监听 80）。

### 为什么必须是“与主站不同的源”

三个硬约束同时成立，只有“独立源 + 沙箱放行同源”能满足：

| 约束 | 要求 |
|---|---|
| 服务器带宽有限 | 预览资源尽量走 OSS/CDN，不压服务器 |
| localStorage 可用（每位访客进度存自己浏览器） | iframe 必须有真实 origin → 沙箱要 `allow-same-origin` |
| 安全不回退（demo 不能碰主站凭据） | `allow-same-origin` 只能在 **iframe origin ≠ 主站 origin** 时才安全 |

同源 `/preview`（主站域名）+ `allow-same-origin` = 任一上传 demo 都能读主站 Cookie/localStorage/调 API（XSS 提权），不可取。

### 版本化 URL 与缓存策略

- 预览 URL 统一带版本号：`/preview/{slug}/v{版本号}/index.html`
- 版本号 = `demo.updated_at` 时间戳；更新 demo 后版本号变化 → 新 URL
- 版本化 URL 响应使用 `Cache-Control: public, max-age=86400, immutable`，CDN/浏览器可放心长缓存
- 旧的无版本 URL（`/preview/{slug}/...`）保留 `no-cache`，兼容历史外链/旧前端
- 这样同时满足：
  - 更新后立即生效（新 URL 不会命中旧缓存）
  - CDN 继续挡流量（JS/CSS/图片等大头走版本化 URL 长缓存）
- 实现位置：
  - `backend/app/main.py`：`/preview/{slug}/v{version}/{path}` 路由，内部忽略 version 服务同一份文件
  - `backend/app/serializers.py`：`preview_url` 拼版本号
  - `backend/app/services/storage.py`：OSS 对象恢复长缓存（版本化 URL 负责 bust）

## 2. 三个坑：现象 / 根因 / 证据 / 修复

### 坑一：localStorage 报 SecurityError → 按钮点了没反应（仅存储类 demo 中招）

- **现象**：滚动的天空/我的世界/pvz 等“开始游戏”点了没反应；Console：`SecurityError: Failed to read the 'localStorage' property from 'Window': The document is sandboxed and lacks the 'allow-same-origin' flag.`
- **根因**：预览 iframe 沙箱未开 `allow-same-origin` → 文档 origin 为**不透明（opaque）**，浏览器规范禁止 opaque origin 访问 `localStorage`。游戏在 `buildCards→bestOf` 读最佳分即抛错。本地打开无沙箱，正常。
- **修复**：预览改走不同源（子域），沙箱对跨源再加 `allow-same-origin` → localStorage 落各访客浏览器、互不共享，且够不着主站凭据。
- **要点**：`localStorage` 本来就是存客户端的、按浏览器/按 origin 隔离的，与账号无关（同账号跨设备不同步；需要账号级服务端存档需另行设计）。

### 坑二：iframe 全白 / `Download is disallowed`（OSS 默认域名对 HTML 强制下载）

- **现象**：改 OSS 直链后**所有** demo 顶部白屏；Console：`Download is disallowed. ... 'allow-downloads' is not set.`
- **根因**：阿里云安全策略：**用 OSS 默认域名（`<bucket>.<region>.aliyuncs.com`）访问 HTML** 时，OSS 对部分地域/时间后创建的桶强制附加
  `x-oss-force-download: true` + `Content-Disposition: attachment`，让浏览器走“下载”而不是“渲染”。
- **证据**：
  ```
  curl -I https://<bucket>.oss-cn-beijing.aliyuncs.com/demos/<slug>/files/index.html
  ```
  ```
  x-oss-force-download : true
  x-oss-ec             : 0048-00000001      ← 策略规则 id
  content-type         : text/html
  content-disposition  : attachment
  ```
- **大坑教训（本次最伤的）**：该 `attachment` 是 **GET 时动态附加的，与对象元数据无关**。
  因此 `update_object_meta` / `copy_object` 改对象级 `Content-Disposition` **全部无效**
  （SDK `head_object` 看是 `inline`，但公共 GET 仍是 `attachment`——改元数据那两轮脚本是无效路径，勿再重蹈）。
- **修复**：预览顶层 HTML 改由**自己的后端 `/preview` 返回**（响应头自己控制，无强制下载）；并把预览 iframe 放到**自备子域**（`demo.deepdemos.top`，香港服务器，无 ICP 备案问题）。
  阿里云中国大陆 OSS 绑自定义域名需 ICP 备案；域名未备案不可走该路。
- **要点**：force-download 只拦“顶层文档导航”，`<script>/<link>/<img>` 子资源不受 Content-Disposition 影响，仍可直接从 OSS 加载（带宽不涨，因为只有 index.html 过服务器）。

### 坑三：能加载但黑屏（ES module import / fetch 跨源被 CORS 拦）

- **现象**：我的世界等“页面有(canvas/标题)但全黑/不启动”。
- **根因**：这类 demo 用 `<script type="importmap">` + `<script type="module" src="...">`，内部 `import {…} from './world.js'`；
  由于 `<base>` 指向 OSS，`./world.js` 变成**跨源**请求，而 **ES module 的 import 强制要求 CORS**。OSS 桶没配 CORS → 模块图加载失败 → 黑屏。（用 `fetch()` 拉数据的 demo 同理。）
- **证据**：
  ```
  请求 OSS 文件时带 Origin 头，响应无 access-control-allow-origin
  Access-Control-Allow-Origin: (none)
  ```
- **修复**：**OSS 桶配 CORS 规则**（控制台 → 桶 → 跨域设置）：
  | 字段 | 值 |
  |---|---|
  | 来源 | `http://demo.deepdemos.top` + `https://demo.deepdemos.top`（**两个都加**，见下方回归教训） |
  | 方法 | `GET, HEAD` |
  | 允许 Headers | `*` |
  | 暴露 Headers | `*`（或 `ETag`） |
  | 缓存时间 | `600` |
  **并勾选「返回 Vary: Origin」**——同一批 URL 同时存在 CORS（module/fetch，带 Origin）与非 CORS（img/普通 script，不带 Origin）请求，必须按 Origin 分层缓存，否则“无 ACAO 的缓存被 CORS 请求命中”会偶发失败。

- **⚠️ 回归教训（已踩）**：全站切 HTTPS（Cloudflare）后 iframe 源变成 `https://demo.deepdemos.top`，但 CORS 规则里只留了 `http://demo.deepdemos.top` → https 来源请求**无 ACAO** → 我的世界类 module 又黑屏。**每次改协议/源后必须同步 CORS 来源**（http 与 https 各留一条）。判断：带 `Origin: https://demo.deepdemos.top` 请求 OSS 文件看有没有 ACAO；acoa 只对 http 生效即来源漏配。

### 坑四：能加载但鼠标视角/WASD 不动，只有 E/F3 这类键有效（Pointer Lock 被沙箱拒）

- **现象**：我的世界能加载出来，但鼠标无法控制视角、WASD/空格不能移动；E（背包）、F3（调试）等键正常。
- **根因**：3D 游戏用 **Pointer Lock**（`canvas.requestPointerLock()` + `movementX/movementY` + `pointerlockchange`）控制视角和移动。
  沙箱 iframe **缺 `allow-pointer-lock`** → `requestPointerLock()` 被浏览器拒绝 → 永远进不了 locked 状态 → 鼠标视角无效；
  且移动通常也挂在 `locked` 门控之后。E/F3 是全局 keydown 开关，不受 pointer lock 门控，所以还能用。
- **证据**：
  ```
  main.js:   this.canvas.requestPointerLock()
  main.js:   document.addEventListener('pointerlockchange', ...)
  player.js: e.movementX / e.movementY           // 只有 pointer lock 后才有
  player.js: if (this.locked) { ... mouse/wheel  // 移动/鼠标动作被 locked 门控
  ```
- **修复**：`IframePreview.vue` 的 sandbox 增加 **`allow-pointer-lock`**。
  sandbox 当前全量：`allow-scripts allow-modals allow-forms allow-popups allow-pointer-lock`，跨源再追加 `allow-same-origin`。
- **要点**：Pointer Lock 需要**用户手势**（点一下画布）才会请求并锁定；按 ESC 退出锁定后需再点击才恢复——这是浏览器正常行为，不是 bug。

### 坑五：画面正常但 WASD 等按键完全没反应（预览 iframe 没有键盘焦点）

- **现象**：`/demo/demo-f23ab4e1`（空病房 · 像素恐怖游戏）打开后按 WASD 角色不动；同一预览地址单独打开则完全正常。
- **先排除 Pointer Lock**（与坑四区分）：该 demo 的移动只读 `input.keys['KeyW']`，指针锁仅门控鼠标视角，
  代码里还显式写了「a failed lock request must not pause」——**移动不吃指针锁**。
- **根因**：键盘事件只送到**持有焦点的文档**。demo 的按键监听挂在 iframe 内的 `window` 上
  （`window.addEventListener('keydown', e => keys[e.code] = true)`），而跨源预览 iframe 默认不持有键盘焦点
  → 按键全落在父页面（站点自己），游戏侧 `input.keys` 永远为空。
- **实测证据**（CDP 探针驱动 headless Edge 152，直接读 iframe 内 `window.__game.input.keys`）：

  | 焦点状态 | 游戏是否收到 W |
  |---|---|
  | 刚打开页面（父页面持焦点） | ❌ `w:false` |
  | 用户真实点击预览后 | ✅ `w:true`（`menuSel` 0→3、位移 +1.465） |
  | 再点页面别处（焦点回父页面） | ❌ `w:false`（位移 0.000） |
  | **程序化 `iframe.focus()`** | ❌ `w:false`（`document.hasFocus()` 变 true 是假象，输入路由不变） |

  → 结论：**只有「用户真实点击预览」才会把键盘焦点交给 iframe**，脚本抢焦点既不可靠也不该做。
- **修复**（`IframePreview.vue` + `styles/components/preview-embed.css`）：
  1. 未持有键盘焦点时，预览左上角显示硬边提示「点击预览后，键盘操作才生效」；
  2. 该提示层 **`pointer-events:none`**——点击穿透到 iframe 本身，靠浏览器原生行为交焦点（绝不 auto-focus 抢键，
     否则会连带吃掉站点的 F/G/`/` 快捷键）；
  3. 判定式 `document.activeElement === iframeEl`（实测可靠）+ 事件驱动（window `focus`/`blur`、document `focusin`/`focusout`、指针按下后校准），**不引轮询**；
  4. 触屏（`(hover:none)`）不显示该提示。
- **要点**：与坑四同源——这是浏览器对跨源 iframe 的正常行为，**不是 demo 的 bug**；站点能做的是把状态说清楚。

### 坑六：Esc 被站点抢走（"我要关游戏菜单，却是站点退了全屏"）

- **现象**：全屏玩 demo 时按 Esc，期望关掉作品自己的菜单，实际是站点退出全屏。
- **根因（两层叠加）**：
  1. **原生全屏**（`requestFullscreen`）下，Fullscreen API **保障**"全屏态按 Esc 退出全屏"——
     网页能收到 keydown 但 `preventDefault` 拦不住这次退出。
     **所以"原生全屏"与"Esc 归作品"在规范上互斥**，这不是能改的 bug。
  2. 站点自己在父文档绑了 Esc：`DemoView`（退 fakeFs）与 `IframePreview`（退 webFullscreen）。
- **修复（本轮定稿的归属约定）**：
  - **全屏改走站内覆盖层**（`.preview-shell.web-fullscreen`，`position:fixed; inset:0`），
    **不再请求原生全屏** —— Esc 不再是"浏览器保留键"，可以完整让给作品。
  - **站点不再绑 Esc 退全屏**；退出靠**覆盖层内的可见按钮**（`.preview-fs-exit`）+ `G`。
    ⚠ 没有 Esc 之后那个按钮是唯一可靠出口，所以它**必须常驻可见** —— 不能做悬停显形：
    预览被 iframe 覆盖，指针落在 iframe 上时父级 `:hover` 收不到事件（实测过）。
  - **站点自己的浮层仍用 Esc**（搜索 / 筛选抽屉 / 确认框 / 公告 / Peek）—— 那是真·站点 UI。
  - `F`（原生全屏）随之退役；`G` 与按钮切换同一个覆盖层。
- **为什么能彻底解决**：键盘事件只送到持有焦点的文档（见坑五）。覆盖层下**站点一条 Esc 都不绑**，
  于是 Esc 要么被作品收到（iframe 持焦点时），要么什么都不发生 —— **不可能再变成"站点退全屏"**。
- **代价（明说）**："全屏"从此是"无干扰的站内满视口"，不是系统级全屏；桌面想要真全屏可按 F11。
- **另修一处与焦点无关的必然冲突**：`<iframe @dblclick="...">` 已删 —— 作品内双击（加速/操作）时，
  外层 iframe 元素同样收到 dblclick，会莫名进全屏。这条与焦点无关，**必然**发生。

### 坑七（结构）：同一件事有两套全屏实现

- **现象**：进全屏的路径不同，退出方式也不同；而网页全屏层**只有 G/Esc 两种退法、没有可见按钮**。
- **根因**：`DemoView` 自持 `nativeFs/fakeFs`（`.dv-stage--fs` + `.dv-fs-exit`），
  `IframePreview` 自持 `webFullscreen`（`.preview-shell.web-fullscreen`）—— 两套状态、两套退出。
- **修复**：合并为 `composables/usePreviewFullscreen.ts`（覆盖层唯一实现 + 成对使用
  `useBodyScrollLock` 引用计数锁，守 RF-2 的教训），`IframePreview` 消费并
  `defineExpose({ toggleFullscreen, exitFullscreen, isFullscreen })`，`DemoView` 只转发按钮与读状态。
- **顺带踩到的 Vue 陷阱**：布尔型 prop **缺省会被强转成 `false`** ——
  裸写 `defineProps<{ hotkeys?: boolean }>()` 会让"调用方没传"变成 false，
  详情页的 `G` 热键**静默失效**（实测症状：window 收到了 `'g'`，但处理器从未挂上、
  `defaultPrevented` 一直是 false）。必须 `withDefaults(defineProps<...>(), { hotkeys: true })`。

### 坑八：站点 chrome 压在画面上 / 互相重叠 / 全屏铺不满（一次实测暴露四件事）

用户报：「全屏状态有组件浮在 demo 上面…独立页 3 个按钮浮在 demo 画面上影响体验，还遮住了点击游戏才能捕获键盘的提示条」。逐条量过，根因有四个，其中两个是**结构性**的：

**① z 令牌表达的是"位置"而不是"重要性" → 最重要的一次性提示被压在最底层**
- 焦点提示（"点击预览后，键盘操作才生效"）用 `--z-overlay: 2`，而按钮用 `--z-local: 10`。
- 于是提示条被按钮盖住（`elementFromPoint` 在提示条中心命中的是 `BUTTON.play-btn`），用户"看不到提示"。
- 修：提示条改**一次性居中 toast**（4s 自动消失 / 点进画面立即消失 / 本会话只提示一次），z 提到 `--z-toast: 1100`。
- **教训**：z 令牌要按"信息优先级"分层；把最该被看见的东西放在最低层，是令牌命名没约束住的结果。

**② `position: sticky` 会创建 stacking context → 固定定位的"全屏层"被关在祖先里**
- 覆盖层是 `position: fixed; inset: 0; z-index: var(--z-fullscreen)`，实测矩形就是视口，**但站点卡片画在它上面**：
  `document.elementsFromPoint(720, 450)` 的栈顶是 `DIV.card.dv-desc-card`，覆盖层只排第 3。
- 原因：祖先 `.dv-stage` 是 `position: sticky`（**sticky 即使 `z-index: auto` 也会创建 stacking context**）。
  覆盖层的 `z-index: 9999` 只在这个上下文**内部**有效；而描述卡是**后面出现**的兄弟
  （`position: relative; z-index: auto`），在父上下文里同级比较时 **DOM 顺序在后者赢**。
- 修：全屏期间把承载覆盖层的祖先自身提上去 —— `.dv-stage--immersive { z-index: var(--z-fullscreen) }`
  （DemoView 按 `fsActive` 绑类）。
- **为什么不用 `<Teleport to="body">`**：把 iframe 移出再移回 DOM 会**重新加载作品**（规范行为），
  等于每次进/出全屏都把游戏重开一遍。
- **教训**：`position: fixed` 不等于"一定在最上面" —— 先看祖先里有没有 sticky/fixed/transform/opacity
  等会创建上下文的东西；这类 bug 在单测里看不见，只能靠 `elementsFromPoint` 这类实测。

**③ 内嵌语境的高度上限泄漏到全屏 → 画面底部空 120px**
- `.preview-shell.web-fullscreen` 的 iframe 实测高度是 **780** 而不是 900。
- 元凶在另一个文件：`styles/pages/demo-detail.css` 的 `.dv-stage iframe { max-height: calc(100vh - 120px) }`
  —— 那是为**内嵌预览**（顶上还有 topbar）写的，全屏时它照样生效。
- 修：全屏规则里显式 `max-height: none; min-height: 0`（权重 `.preview-shell.web-fullscreen .preview-frame`
  (0,3,0) > `.dv-stage iframe` (0,1,1)）。
- **教训**：一条写在"页面级"文件里的规则，会跨语境命中同一元素；全屏这类"语境切换"必须显式复位。

**④ chrome 自己会互相重叠 + 悬停状态泄漏**
- 覆盖层右上角同时存在 `.preview-fs-exit`（12,12→1428,56）与 `.preview-hint`（1262,16→1424,45），**实测矩形相交**
  —— 而且 hint 的文案「按 G 或点右上角退出全屏」与被压住的按钮**完全重复**。
- 修：两者合并为**一个两态控件** `.preview-chrome`（展开 = 带「退出全屏」文字；收起 = 36px 半透明锚点，
  hover/聚焦由 **CSS** 展开）。
- 期间踩到：曾用 JS 的 `hold()/release()`（`@pointerenter/@focus`）维护"悬停时保持展开"，
  一旦 enter 没有配对的 leave（切窗口、指针被移走、程序化 blur…）就**永久卡在展开态** ——
  症状正是用户说的"东西一直浮在画面上"。现在 JS 只管计时，**无状态可泄漏**。

> **过程教训（工具也会骗你）**：我一度以为"chrome 不会自动收起"，因为探针在 700ms 就跑完了 ——
> 真相是我的 CDP harness 忽略了 job 里的 `after` 字段（`if (j.js) { …; await sleep(700) }`）。
> 修好 harness 后一次就通过。**当一个结论与代码逻辑明显矛盾时，先怀疑测量工具**，
> 并把这条写进工具注释里。

### 坑九：验收快照里的图片 —— "自包含"是假的，而且一致性校验会替你圆谎

题目行接真实封面后，验收页要能从 `file://`/静态服务打开。三件事必须一起做，缺一件就会出现
"看起来验收通过了、其实什么都没证明"：

**① 只内联字体不内联图片 = 假自包含**
- 快照生成器原本只把 `woff2` 换成 data URI，`<img src="/media/...">` 原样保留 —— 页面在
  dev server 开着时看着完美，dev server 一关图全开天窗。
- 修：抽取阶段把所有 `<img src>` 也 `fetch` → data URI（lazy 图即使还没解码也能 fetch 到，
  这里走网络、不依赖 `<img>` 的加载状态），并**在页面里和 node 侧各断言一次**
  （`img:not([src^="data:"])` 必须为空、HTML 里不许残留 `src="http…"`），不满足直接抛错。

**② `loading="lazy"` + 整页截图 = 一排空框，而 live/static 两边都空 → 哈希照样相等**
- 这是最危险的一条：`Page.captureScreenshot({captureBeyondViewport:true})` **不会替你滚动**，
  视口外的 lazy 图永不解码；live 与 static 因此都是空框，SHA-256 相等 —— **校验通过，却是在
  验证"两个空页面长得一样"**。
- 修：截图前**滚到底再回顶**（`shot.mjs` 加默认前置步骤），快照生成时把视口高度设到能容下整段，
  并且**把 `naturalWidth > 0` 的数量当断言**（`expectCovers`），不是当参考信息。
- 顺带保留原有的兜底超时：不带超时的 `Promise.all(imgs)` 会因为视口外的 lazy 图永不触发
  load/error 而**永久挂住截图流程**。

**③ 一致性校验要报"差异的性质"，不能只报一个哈希**
- 本轮 1440 视口出现 180 个差异像素。只报"SHA-256 不同"会让结论卡在"到底哪里不一样"。
- 现在的判定链：**分区域差异统计**（模型段/题目段/标签段各多少）+ **连通块大小分布**
  （孤立 ≤7px = 抗锯齿抖动；成片连通块 = 真实位移）+ **同页连拍两次作对照**
  （本轮连拍逐字节相同 → 排除截图随机性 → 那 180 个像素是 live/static 光栅化的真实细微差异，
  且全在未改动的模型段）。
- 另加一条**结构证明**（比像素更硬）：把本次新增的元素/类/`v-if` 占位注释规范化掉后，
  改动前后两份快照应**逐字节相同** —— 它回答的是"这轮到底改了几处"，像素比对回答不了。

> 三条合起来的规则：**验收页的每个"一致"结论都要能被反问一句"你是怎么知道的"**，
> 并且答案里要有"如果不一致会怎样被发现"。

## 4. 事故复盘与过程教训

1. **别只看“对象/接口视角”，要验证“客户端真实路径”**。本次元数据改完 SDN `head_object` 显示 `inline`，但公共 GET 仍是 `attachment`——
   以 `curl -I`/浏览器实测响应头为准（content-type、content-disposition、`x-oss-force-download`、`access-control-allow-origin` 全要看）。
2. **未经验证的方案不要推全量**。OSS 元数据脚本（update_object_meta / copy_object）对坑二根本无效，幸而 copy 版未执行。
   思路验证应先在**小范围（2~3 个对象）**成功、再全量。
3. **本地命名 bug 就能让整轮修复失效**：后端返回 `preview_url`（snake_case，与 `cover_url` 同风格），前端写成 `previewUrl`（camelCase）
   且 getDemo 原样透传无映射 → 字段永远 undefined → 静默回退旧路径。**前端类型必须与 API 契约字段严格一致（本项目一律 snake_case）。**
4. **阿里云平台策略优先查官方文档 + 抓 `x-oss-*` 标记**：`x-oss-force-download`/`x-oss-ec` 直接定位“安全策略强制下载”，
   不要先去猜“CDN 缓存/对象元数据”。官方文档《如何配置访问OSS文件时的预览行为》即场景排查表。
5. **面向广域的 iframe 内容（用户上传 demo）安全优先级很高**：允许 `allow-same-origin` 的唯一安全方式就是“与主站不同源”；
   任何“同源 + allow-same-origin”都等于把主站 Cookie/API 交给上传者。
6. **带宽与成本意识**：能走 OSS/CDN 的资源（js/css/img/数据）绝不压服务器；只有“顶层 HTML”这类必须由自己控制的响应才走后端。

## 5. 回归冒烟清单（改动预览相关代码后必测）
